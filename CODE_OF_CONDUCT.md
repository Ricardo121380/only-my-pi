# Code of Conduct

We want only-my-pi collaboration to be technically rigorous, respectful and
safe. Participants must:

- discuss people and ideas without harassment, threats, discrimination or
  personal attacks;
- give actionable technical feedback and assume good faith while still
  requiring evidence for security and compatibility claims;
- respect privacy: never expose another person's credentials, sessions, host
  paths, private repositories or model output;
- avoid spam, impersonation, deceptive artifacts and undisclosed conflicts of
  interest;
- follow maintainer instructions when a discussion needs to be narrowed,
  moved to a private security channel or paused.

This applies in repository Issues, pull requests, Discussions and other spaces
the project directly moderates. Maintainers may edit, hide or remove content;
close or lock threads; reject contributions; or temporarily/permanently block
participation when needed to protect the community or project.

For ordinary conduct concerns, contact the repository owner through a private
GitHub channel where available. Security vulnerabilities must use GitHub
Private Vulnerability Reporting as described in [SECURITY.md](SECURITY.md).
Do not publish sensitive evidence while seeking help.
