# ADR-0019: 直接采用 Pi 1.1.0 开发基线并纳入 MCP 与 codemode

2026-10-17 后继方向：用户明确 Only my pi 同时交付直接基于最新稳定版 Pi 的 CLI/TUI 与桌面客户端，图形端先完成 WebUI。按[当前迭代计划](../plans/2026-10-17-product-direction-and-iteration-plan.md)逐轮核对并锁定上游稳定版，下一目标为 1.3.0；本决定的 1.1.0 固定开发目标由此更新为历史适配基线。MCP/codemode 范围、独立适配先行、原 WebUI 出口及证据边界继续有效。实际开发依赖仍为 1.1.0，本轮没有执行升级，也没有用新目标覆盖旧合同或验收。

当前产品仍在开发中，用户决定直接将现有开发依赖升级到 Pi 1.1.0，再通过 grill-with-docs 确定适配方案，随后执行 to-spec 和 to-tickets；不继续将 0.85.1 作为本轮冻结的开发目标。历史版本合同与验收记录保留原身份，不作为新版本通过的证明。

用户已确认本轮同时接入 MCP 和 codemode，扩大规格与验收范围；缓存保温本轮关闭、未来另行接入；TUI 默认采用 fullscreen，保留 regular 选项，WebUI 的 Glacier 布局保持既有产品约定。2026-10-10 进一步确认：MCP 同时支持 stdio 与 Streamable HTTP，由 OMP 独立管理配置、凭据引用及项目覆盖，并支持显式导入；codemode 同时支持分类和图片生成，完整纳入显式模型选择、授权、预算和用量。具体授权与执行策略继续按讨论确定，不能从“接入”推定任意服务器或模型已获授权。

本决定更新 [ADR-0014](ADR-0014-webui-to-electron.md) 与 [ADR-0017](ADR-0017-versioned-runtime-contracts-and-stack-promotion.md) 中本轮开发目标的版本限定和升级先后顺序；不撤销会话/账号/所有权边界、历史证据或用户数据保护。开发依赖更新、完整适配、实际安装仍分别报告。完整设计和测试边界以[本轮讨论记录](../plans/2026-10-09-pi-1.1.0-adaptation-discussion.md)的最终共识为准。
