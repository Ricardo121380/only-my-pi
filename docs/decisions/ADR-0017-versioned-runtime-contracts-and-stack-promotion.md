# ADR-0017: 以版本化运行合同和栈内扩展完成日常安装晋升

用户要求第一阶段在技术验收通过后升级日常 OMP CLI，而已安装 legacy Full 栈、候选 Pi 0.85.1 和当前借用的用户外部扩展有不同的身份与补丁约束。采用新旧并存的版本化运行合同、候选栈内独立扩展副本，以及“候选技术验收 → 日常切换 → 显式回滚 → 同候选重新应用”的晋升流程，保证新栈可追溯且旧栈仍可校验恢复。本决策是已确认设计，尚未实现或验收。

## 决策与取舍

- 分开记录开发依赖、候选发行运行核心和日常实际安装；修改根 package.json 不能作为升级完成证据。
- 保留旧版本合同和历史 M9/M10 回执；新增候选合同绑定 Node/Pi/外部包精确版本、完整性、源码、产物树及补丁摘要，不全仓替换旧版本常量。
- macOS 候选从精确 Pi 包构建，不继续复制旧 seed 后更改版本声明。候选必须实际运行 Pi 0.85.1。
- 用户原外部包保持原样；候选加载栈内独立的受控副本。副本随栈验证、升级和回滚，不把用户原包的归属改为 OMP 所有。
- 补丁按精确运行合同选择，预期集合必须完整。未知输入摘要、缺失补丁和不兼容资源过滤均阻止候选晋升。
- 继续沿用本机 legacy Full 栈渠道，由支持新旧合同的候选管理器执行 update/rollback；不改成 npm 全局安装或渠道迁移。
- 回滚目标是本次切换前重新核验的 active stack，不是更早的 LKG。若 active 在核验后发生变化，停止切换并重新绑定基线。
- M1-T 代表候选技术验收通过；M1-I 代表日常切换、回滚和同一候选重新应用通过。两个检查点均通过才算 M1 完成。
- 切换前存在用户正在使用的相关会话时，保持待切换，不强停。候选包、管理器和回滚材料保存于可能被回滚删除的栈目录之外。
- 凭据与会话是用户数据；升级回滚不以旧快照覆盖合法的新 token 或新历史。正常运行变化与安装事务变化分别记录。

与继续借用共享外部包相比，栈内副本增加了构建和存储成本，但避免候选补丁覆盖用户原包，也使新旧栈的实际运行内容可以独立证明。保留旧合同增加兼容代码，却是可验证回滚所必需的边界。
