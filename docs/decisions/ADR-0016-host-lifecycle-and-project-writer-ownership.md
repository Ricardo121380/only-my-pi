# ADR-0016: Host 持有执行生命周期，人工与 Agent 共用项目写入所有权

用户希望关闭或刷新界面后，已授权任务继续工作，同时要求同一项目的人工编辑、终端和 Agent 轮流写入。执行生命周期因此归属于 Host/worker，项目写入所有权跨 CLI、GUI 与人工工具协调；页面存活不再作为任务存活的唯一条件。本决策是已确认设计，尚未实现。

## 决策与取舍

- Host 存活时允许已授权任务继续，新审批等待界面重连；失效或被替代的答复不授予权限。明确退出 Host 会取消任务、关闭 PTY 并使待审批失效；重启不恢复编程授权。
- 编程授权与项目写入所有权分离：前者决定允许的范围，后者决定当前执行方。已有权限不等于可以与另一个执行方同时写入。
- 写入协调覆盖主 Agent、受管补丁应用、真实工作区检查、编辑器保存和人工终端；不能仅依赖单个 Host 的内存状态或单个 orchestrator 的 writer 标记。
- 跨项目可以并行；同项目只有一个写入所有者。人工编辑在显式手动模式下保存，切换前处理未保存内容。
- 人工终端存活期间持有项目写入所有权，关闭终端及其子进程后才释放。页面关闭或刷新不自动让 Agent 接管终端正在占用的项目。
- 只续接已停止的会话；会话历史占用和项目写入所有权分别核验。Host 崩溃后必须检查遗留进程，不能仅凭超时抢占项目。
- 普通 headless 和 `omp -p` 保持只读。GUI 采用受控交互宿主，审批继续经过 OMP 的身份、代次和撤权检查。
- 补丁“已应用”与项目“已验证”分别记录；应用结果未知时保留待核对状态，禁止因重连自动重试应用。

与页面断开即取消相比，该方案更适合长任务，但增加了进程管理、可观察状态和重连责任。终端全生命周期独占比自动识别 shell 空闲更保守，可避免后台子进程仍在写入时错误放行 Agent。
