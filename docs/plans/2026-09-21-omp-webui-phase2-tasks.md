## A03 当前实施顺序

1. 保留 `RpcWorker` 的进程树终止、输出上限、错误脱敏及命令白名单。
2. 增加固定版本 Pi 公共 SDK 的受控入口；不通过更换整个 `PI_CODING_AGENT_DIR` 冒充身份注入，以免改变策略、历史或扩展归属。
3. 将服务端解析的账号身份交给入口，入口从私有目录重新校验；不接受浏览器路径、环境变量或任意启动参数。
4. 显式选择 Provider/model，验证对应存储认证；同时检查环境、HOME 派生认证、静态配置和扩展注册 Provider 的回退路径。仅清理环境变量不足以验收。
5. 保留已审计的扩展集、只读工具 allowlist、权限模式及共享历史目录；SDK 诊断不直接转发原始错误。
6. 模拟服务验证实际请求身份及失败不回退，再接 A04。A03 未通过前，不开放 GUI 账号执行任务。

## 执行与交付纪律

- 每个 Task 的进度更新写入 progress 文档，包括改动文件、测试命令、结果和限制。只有证据支持才更新完成状态。
- 不要求用户逐 Task 重复授权；范围内自主推进，真实阻碍或新增权限边界才询问。
- 不升级 Pi、不新增数据库、不改 CLI 默认认证、不推送或发布。
- 现有未提交内容保留；阶段候选提交按计划收口，不混入无关改动。
- 全量构建前重新检查磁盘；本看板不授权额外清理。
