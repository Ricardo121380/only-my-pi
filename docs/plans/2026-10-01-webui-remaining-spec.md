## Problem Statement

项目已有连续对话、任务控制和多轮技术验证，但产品计划、材料补齐、发行接线及验收记录分布在不同文档中。任务拆分若先于本次范围和测试边界的共识，容易出现“材料探针通过即认为产品完成”“局部技术验证即认为 Full 可安装”或无法追溯工单为何存在的问题。

用户需要在 CLI 和图形端独立设置账号、工具及认证，以同一项目和会话继续编程，保留明确的账号归属、材料与结果；换一个入口时，设置、权限、用量和历史必须保持可解释。文件和文档输入、项目整理、审查、预览及可恢复的实际安装仍属于完整产品范围。

目前已有功能与这些新增承诺分属不同候选和批次，局部实现或旧版本验收不足以证明双端日常使用完整。维护者需要看清每项工作还需交付什么、真正依赖谁、在哪个实际入口验收，避免把材料阻断扩散为所有独立功能停工，或以修改版本号和工单数量代替产品进展。

本规格把已确认目标组织为需求 → 工单 → 原 Task → Gate → 候选身份与证据 → 状态的对应关系。历史基线移至 Further Notes 保留；当前产品范围和验收条件由以下章节定义。

## Solution

交付直接使用 Pi 核心的 CLI/TUI 和桌面正式客户端；先完成本机单用户中文 WebUI，延续 Glacier、对话优先、右侧按需审查和真实终端入口，再进入桌面。新增核心能力先在 macOS arm64 两端对等，既有 Linux CLI 保持兼容。图形端沿用 React/TypeScript/Vite，Pi 接入优先核对公开 SDK，必要进程隔离可用 RPC；当前 Host/worker 属于可调整的应用实现，不是额外 Agent 内核或产品阶段。下一已查证目标为 Pi 1.3.0，当前开发依赖为 1.1.0；每批再核对稳定版并冻结实际候选，按 Q6 保留能力优先的回退路径。

总规格保留 Pi 1.1.0 批次已选的 MCP 两种连接及受控写入、codemode、分类/生图和会话产物，增加当前稳定 Pi 适配及双端共同能力；G2-00、材料输入 U2、项目与历史 U3、结果与用量 U4、资源与预览 U5、整合与日常验收 U6 全部保留。已有 #20–#75 不重建，进入各批前核对实现、候选身份和前置；新增工作只补真实缺口。一个原 Task 可对应多张独立工单，全部子项和门禁满足后才改变其状态；原 44 项产品分母、GP110 历史批次与 GP130/GCLIENT 新范围分别追踪。

业务测试分别经过实际 CLI/PTY 与图形端公开入口并与真实 Pi 集成；界面测试经过 Ego Lite 实际用户旅程；材料与发行测试经过固定探针、默认发行链和当前候选的隔离 Full 安装。CLI 独立能力不能由 GUI 预配置或仅调用共享函数代验。局部单测补充边界与异常。规格发布、可执行工单、实现完成、技术验收、安装验收和日常晋升各有独立状态。

交付顺序沿 2026-10-10 适配 Q12，并由当前蓝图 Q3/Q12 细化：Pi 兼容和不依赖 parser 的功能可以先行。#39/#40 的独立元数据合同验证后可去除完整 #38 的开工依赖，#41/#42 保留真实索引前置；同步给 #43 显式补回 #38，#44 保留完整 U2/分支汇合。原材料链继续由 #20/#21/#22 → #23 → PDF/资源构建 → 默认发行 → G2 隔离 Full 推进，Q7 的替代评估不自动替换这条链。使用 parser 的功能保留 G2 前置，U3–U6 完整出口和全部已选范围保留；具体远程依赖仍待同步，不以本段宣布已放行任务。

MCP 由 OMP 独立管理配置、凭据引用和项目覆盖，支持显式导入；同一受控配置服务 CLI/TUI/WebUI。服务器启用不等于授权调用。codemode 逐工具及逐模型执行当前策略；分类与生图有各自的账号/模型绑定、有限预算、可追溯结果和会话产物。缓存保温本轮关闭；TUI 默认 fullscreen，保留 regular。

## User Stories

**工程追踪与既有能力**

1. **US-001** 作为维护者，我希望每项需求能找到对应工单、原 Task、Gate 和证据，以便判断开发目标与完成条件。
2. **US-002** 作为维护者，我希望保留 S0/U0/U1 的原身份、范围和历史验收，以便继续开发而不重开已完成任务或把旧证据当作新候选通过。
3. **US-003** 作为维护者，我希望提前看到全部剩余功能、可验收切片与真实依赖，并在进入每批前复核，以便控制每次实现范围且让远期工单与最新事实保持一致。
4. **US-004** 作为日常用户，我希望编程授权、单写所有权、真实终端、连续输入和历史恢复规则在新功能中继续成立，以便新增能力不破坏已有工作。

**G2-00：材料、资源和安装入口**

5. **US-005** 作为维护者，我希望固定 source、patch、tool、lock 和完整 vendor 输入，以便确认当前候选由哪些确定材料构成。
6. **US-006** 作为维护者，我希望 libexif CSS 组合能对应实际 Doxygen 模板、版本、规则和配置，以便核对完整生成内容与必要声明。
7. **US-007** 作为维护者，我希望五个 Graphviz 图及其余 libexif 生成数据有工具来源、图输入、生成步骤和分发记录，以便复验文档归档而不从标记猜测来源。
8. **US-008** 作为维护者，我希望当前 GIR 材料候选逐项绑定实际取得的固定供应包或源码、版本、加工链与手册引文，以便复验新候选并保留未核历史的真实范围。
9. **US-009** 作为维护者，我希望其余八项生成输入和 111 个宏/脚本的工具来源与当前操作条件闭合，并逐项追踪后续构建和分发义务，以便各阶段都有可核验的准入与完成条件。
10. **US-010** 作为维护者，我希望已验收的 Windows、gettext、xmlwf、locale 和 libexif 子集及其失败记录继续保留，以便新增取证不会覆盖或夸大历史结论。
11. **US-011** 作为维护者，我希望补充材料合入独立的新 native kit，并实际核验完整文件集合，以便用新身份复验 G2-00-02 出口且仍可检查旧 kit。
12. **US-012** 作为维护者，我希望 PDF 辅助资产及实际构建输入有完整对应链，以便字体、CMap、worker、辅助模块和 QuickJS 不依赖开发机隐含资源。
13. **US-013** 作为维护者，我希望新 native 与 PDF 资源候选重新建立身份并完成适用矩阵，以便旧 dylib 或旧 F01 结果不会替代新候选验证。
14. **US-014** 作为维护者，我希望正常默认发行流程纳入 parser 资源、获取台账、双 SBOM、notices 和最终包内容合同，以便常规产物实际带齐这些内容。
15. **US-015** 作为维护者，我希望当前 Full 在隔离环境中真正断网安装并从包内运行图片和文档矩阵，以便确认不回退到 checkout、全局依赖或旧资源。
16. **US-016** 作为产品开发者，我希望 G2-00 在完整必需出口通过后才放行 U2，以便后续材料功能依赖可安装的真实候选。

**U2：材料与文档输入**

17. **US-017** 作为用户，我希望通过独立上传或引用流程准备材料，看到原子完成的状态和消息绑定，以便未完成上传不会被发送。
18. **US-018** 作为用户，我希望仅引用当前项目允许的路径，外部文件由我显式上传，以便材料入口不读取任意主机内容或通过链接越界。
19. **US-019** 作为用户，我希望通过 @文件、代码选区和文本材料卡片选择、预览、移除内容，以便发送前看清来源与范围。
20. **US-020** 作为用户，我希望发送前文件变化时重新确认或使用已冻结快照，以便模型收到的内容与我的选择一致。
21. **US-021** 作为用户，我希望粘贴或拖入 PNG、JPEG、WebP 后，实际 Pi 请求包含对应图片，以便图片作为真实输入参与任务。
22. **US-022** 作为用户，我希望图片解码、像素和转换受限且可解释，不支持图片的模型阻止发送并保留草稿，以便不会静默丢图或换模型。
23. **US-023** 作为用户，我希望文字 PDF 的内容保留实际页位置并支持选页，以便核对出处及控制发送范围。
24. **US-024** 作为用户，我希望 DOCX 正文和表格以段落、标题、表格位置呈现，以便引用真实结构而不伪造 Office 页码。
25. **US-025** 作为用户，我希望 XLSX 保留工作表与单元格位置，并区分公式文本和已有缓存值，以便理解数据且不执行公式。
26. **US-026** 作为用户，我希望 PPTX 保留幻灯片位置并支持局部选择，以便发送所需内容。
27. **US-027** 作为用户，我希望扫描件、加密文档、旧版格式、损坏或部分解析有明确结果，以便不会把缺失内容误认为完整解析。
28. **US-028** 作为用户，我希望上传、解码、展开、文本、时间和资源上限由实际接口及 worker 执行，以便异常材料不会拖垮 Host。
29. **US-029** 作为用户，我希望模型上下文容量与解析上限分开检查，超限时选择范围、未知时看到说明，以便不会遭到静默截断。
30. **US-030** 作为用户，我希望发送时冻结实际文本/图片、版本、摘要、解析器及范围来源，以便原文件修改或删除后仍能核对历史输入。
31. **US-031** 作为用户，我希望查看并显式清理原上传和发送快照，保留分支共享引用且不误删项目原件，以便可控地管理空间。
32. **US-032** 作为用户，我希望磁盘不足时拒绝新写入并保留旧历史和草稿，以便空间故障不触发自动清理。
33. **US-033** 作为用户，我希望文字、图片、文档与引用在排队、刷新、重连和历史中保持一致，以便卡片、消息 ID、Pi 实际输入和安装态能力能相互核对。

**U3：项目与历史**

34. **US-034** 作为用户，我希望创建、重命名、排序项目分区并调整归类，以便整理工作而不移动项目目录。
35. **US-035** 作为用户，我希望重命名、置顶、归档和恢复会话，以便管理列表而不删除历史或误停任务。
36. **US-036** 作为用户，我希望搜索已登记项目名称及用户/助手消息全文，以便跨项目找到已有讨论。
37. **US-037** 作为用户，我希望搜索支持归档过滤、正确片段和消息定位，以便从结果回到准确上下文。
38. **US-038** 作为用户，我希望索引增量更新、可重建/取消，并明确损坏、陈旧和不完整状态，以便不把失真结果当成完整历史。
39. **US-039** 作为用户，我希望检索范围排除凭据、全盘扫描、隐藏推理和工具二进制，以便只索引已约定的信息。
40. **US-040** 作为用户，我希望从停止会话的有效指定消息创建新身份分支，以便保留源位置并从选定消息继续。
41. **US-041** 作为用户，我希望分支不回滚当前项目文件、不继承授权、队列或活动进程，以便会话分支不会暗中改变工作区和执行资格。
42. **US-042** 作为用户，我希望分支共享历史附件引用、缺失材料可见、继承用量与新消费分开，以便理解分支实际拥有的内容与成本。
43. **US-043** 作为用户，我希望搜索、打开、续接、分支、归档、恢复和旧格式历史形成完整旅程，以便整理功能能投入日常使用。

**U4：结果审查与用量**

44. **US-044** 作为用户，我希望分别看到执行结束、改动已应用和验证结果，以便不把任务停止当成验证成功。
45. **US-045** 作为用户，我希望摘要与统一 diff 能回到实际命令、文件、回执和来源，以便确认改动归属并保留已有用户修改。
46. **US-046** 作为用户，我希望应用状态未知时先回读核对，以便不会因恢复操作重复应用写入。
47. **US-047** 作为用户，我希望请求、工具、任务、会话和主/子 Agent 用量由稳定身份关联并去重，以便重连、续接和重复事件不增加消费。
48. **US-048** 作为用户，我希望看到用量来源、覆盖率、未知或部分状态，并将真实零值区别显示，以便不会被缺失数据误导。
49. **US-049** 作为用户，我希望缓存字段保留 Provider 原含义、聚合时不双计，以便不同路由的数据可解释。
50. **US-050** 作为用户，我希望费用估算绑定请求当时的价格与币种快照，以便设置更新不会重算历史费用。
51. **US-051** 作为用户，我希望上下文指标来自实际请求或运行时快照，以便不会把累计 token 当作当前上下文。
52. **US-052** 作为用户，我希望输出速度按有效生成时间计算、首 token 延迟另列，以便排队和工具等待不扭曲速度。
53. **US-053** 作为用户，我希望输入区提供简洁统计并可展开来源和限制，以便了解当前任务而不挤占对话。
54. **US-054** 作为用户，我希望旧历史、分支、取消、失败和长输出仍保留正确归属与计量，以便特殊状态不会造成重复收费解释或丢失结果。
55. **US-055** 作为维护者，我希望至少在明确支持的夹具中贯通全部选定数据来源，以便“全部未知”不能充当用量功能完成。

**U5：项目资源、命令和预览**

56. **US-056** 作为用户，我希望浏览已有技能/扩展的来源、归属、兼容性和必需集合，以便理解当前可用资源。
57. **US-057** 作为用户，我希望在 CLI 与图形端读写同一套产品默认值、项目覆盖和重置覆盖，以便两端使用一致的项目配置；原 Pi/用户外部配置保留原归属，仅显式导入。
58. **US-058** 作为用户，我希望仅对声明配置 Schema 的资源编辑配置，以便无 Schema 的资源不会假装支持任意设置。
59. **US-059** 作为用户，我希望可选资源可启停而必需安全集合不能关闭，以便保持既有权限边界。
60. **US-060** 作为用户，我希望配置只影响下一次执行，区分请求值、待生效值和实际加载值，以便活动 worker 不发生隐式热变更。
61. **US-061** 作为用户，我希望旧 revision 的排队项暂停确认、加载失败显示原因并保留最后有效产品配置，以便资源变化不会偷偷改变任务语义。
62. **US-062** 作为用户，我希望配置并显式运行具名测试/构建命令，看到真实工作目录、状态、退出码和日志，以便能核对项目验证结果。
63. **US-063** 作为用户，我希望命令发现不自动执行，写命令遵守项目所有权，取消与残留清理有证据，以便不会与 CLI、Agent 或人工编辑冲突。
64. **US-064** 作为用户，我希望 Agent 改动与受管预览真正同时运行且页面持续更新，以便边开发边查看变化。

## Implementation Decisions

**沿用既有架构与状态语义。** Pi 负责 Agent loop 和执行历史；Host 管理认证、账号选择、项目授权、单写协调、输入意图与资源配置。编程会话、执行任务、Host 认证会话和账号各自独立。打开历史不恢复授权；账号缺失不隐式切换。页面关闭与 Host/worker 生命周期分开，Host 退出后待处理输入暂停。收到 SDK ACK 只表示接收/排队，消费需匹配持久 inputId；丢 ACK 先读回执，缺回执不等于未执行，不承诺任意故障 exactly-once。新材料和分支继续维护这一关联。

**双端共同合同。** 上段描述现有图形接入职责，不强制 CLI 依赖 Host，也不预选新增常驻服务或共享框架。客户端各自可操作产品账号与配置，共用必要的身份、权限与协调语义。账号使用/变更协调须覆盖两个实际进程，不能只靠单个 Host 内存计数。工具/配置导入只在显式选择后发生；新建、登录、导入与启用分开，读取清单不运行命令或调用模型。

会话身份同时核对项目、原 Pi 历史、允许的会话根及产品元数据；自定义根由明确登记或选择纳入，不隐含扩大扫描。历史绑定只记录非秘密账号标识，旧记录无绑定时显式选择；绑定失效不自动换账号。任务彻底停止后允许用户显式切换账号，新任务追加绑定，旧调用与用量归属不变。双端交接复用 Pi 公开历史入口并保留源文件，活动/占用会话只读；执行前在真实准入处核验单会话执行和项目单写，取消、进程退出及未知残留分别处理。

配套运行组合至少关联客户端、Pi/扩展、配置与历史合同的实际身份及验收记录，不能只比较 Pi 版本号。未验证组合在共享会话写入或启动执行前拒绝，只展示可读历史；不可读则保留原件并说明原因。用户自行按明确安装流程取得匹配版本，不由一个客户端偷偷更新另一端。版本组合、老数据与进程竞争均须由实际入口验证，不以新增字段或界面禁用代替。

**结果与计量。** 执行、应用、验证是三个结果维度，diff 以实际回执和来源为准。请求与工具有稳定身份，聚合覆盖任务/会话/主子 Agent、重连/分支/重试去重；未知、部分、真实零值不同。缓存语义与来源保留；价格和币种按请求快照计算，历史不随现设置重估。上下文使用实际请求或 runtime 快照，输出速度按有效生成时间计算，排队和工具等待排除，首 token 延迟另列；缺时间戳或来源则明确未知。

**资源配置与预览。** 既有 U5 继续整合已有技能/扩展，区分 stack 自带、用户及项目资源与兼容性；本次新增的 Pi 内置 MCP/codemode 按下述已选范围接入，不建设任意插件市场。按 2026-10-17 Q9，两端共用的产品默认和项目覆盖具有 revision，重置覆盖后继承产品默认；原 Pi/用户外部配置不被改写，仅显式导入。工具/技能设置及分类、生图模型绑定均属于此产品范围，两端写入冲突须明确处理，不能静默覆盖较新值。仅声明 Schema 可编辑，必需集合不可关闭；新配置注入下一次执行，活动任务不热切，队列遇旧 revision 暂停，失败保留最后有效配置并区分请求/待生效/实际加载。撤权、停用及凭据失效仍按原合同阻止后续调用。

具名命令显式执行并记录真实目录/退出码/日志，写命令沿单写协调。受管预览使用 U0 已验证的固定配方和隔离源/派生产物；Agent 与预览需同时工作。端口不同和浏览器 CORS 均不足以证明凭据隔离：需要复验同主机 cookie、环境/请求头泄漏、服务端伪造 Host/Origin/协议头对 HTTP 与 WebSocket 的重放；localhost 与 127.0.0.1 两条访问路径分别复验。预览显示确切本机来源；嵌入受限时可显式打开同一受管预览的独立标签，继续执行来源校验。隔离结论限定本机协作威胁模型与已验证配方，不承诺任意恶意代码的 OS 沙箱。预览不能成为任意 URL 代理；关闭面板不杀服务，停止按进程身份核对，未知残留不得误回收。新增容器、全局权限、公开端口或下载用户项目依赖需另有具体范围授权。

**阶段依赖及晋升。** 原 U2–U6 整体出口保持；#39–#42 等独立整理功能按顶部已确认方向和具体工单差异调整开工依赖，不能把原整批顺序继续用作所有功能的强制阻断。涉及 parser 的动作仍保留 G2 前置；U3 分支依赖 U2 快照及已验证 Pi 分支入口，完整 U3 仍须 U2。U4 用量依赖 U0 的实际字段合同；U5 预览依赖 U0 并行/隔离 PoC 和具名命令。新增共享能力与原范围在 U6 同候选汇合：先入口整合与性能，再同源码 Full 安装，再获具体授权的 Provider 包，最后核对活动/权限后日常升级、回滚切换前已验证 active、重新应用。保留新历史与凭据，禁止强停用户工作。全部选定能力和门禁通过才进入 Electron 3A。

**Pi 1.1.0 与新增能力的执行合同。**

以下设计约束已由 Q13 确认；规格发布不授权直接运行用户 MCP、调用付费模型或切换日常安装。

### MCP 配置、身份与启动

- 新建或导入后展示连接目标、启动命令、能力和配置来源，由用户明确启用；导入不执行命令、不登录、不启动服务器，也不改写原配置。
- 全局默认与项目覆盖使用可追溯的配置版本。任务固定其已选择的配置；修改进入后续任务，当前任务不悄悄换目标或扩大权限。撤销授权、停用或凭据失效应阻止后续调用，已发请求如实结算。
- 配置文件、扩展注册、内置发现及 direct/deferred/codemode 等暴露方式都受同一准入规则约束；工具是否向模型展示与能否调用分别判断，不能靠隐藏工具维持权限边界。
- 秘密通过 OMP 管理的凭据引用取得，不交给脚本、聊天历史、公开状态或日志；不同项目/连接的身份绑定必须可区分。显式复用凭据引用不授予新的工具权限；覆盖目标后不沿用旧目标的登录或授权。
- 远程连接包含显式认证/登录、取消登录、失效与撤销流程；本地服务器采用有限环境和可确认的进程生命周期。导入中的动态命令取密、环境继承或 Provider 认证转借，须转换为受控配置或明确拒绝，不能自动执行。
- 读取 MCP 资源同样检查授权、目标和返回大小；不把远端 HTML 或 MCP Apps 变成新的可执行页面。服务声明的只读、幂等及破坏性注解只作展示依据，不替代 OMP 的实际权限判断。

### 工具、编程授权与取消

- codemode 的父工具授权不代替嵌套调用检查。MCP 写入当前项目，须同时满足工具授权、编程授权及当前任务持有的项目写入所有权；只读任务不能借外部工具写入项目。
- 本地服务器的启动本身可能产生副作用，必须经过受控启动准入和路径/凭据隔离；无法落实隔离的连接不获得该项目的写入准入。并发调用中，项目写入按原单写规则协调，不能仅用工具名称或服务器提示分类。
- 每次执行有有限的时长、并发、输入/输出和结果存储额度；脚本不能扩大 Host 所允许的额度。适用具体上限进入可验证配置和工单验收，不使用无限默认值。
- 已发调用具有稳定身份，关联任务、父脚本、服务器/模型、配置版本及授权范围。取消阻止新调用、撤销待处理审批和排队工作，并对已发调用及进程残留核对结果。
- 脚本失败或取消不撤销已产生的外部副作用；已完成、失败、取消请求和结果未知分别呈现。不自动重放结果未知的写入或模型请求，不把本地取消确认称为远端已停止或零费用。
- 延续 Host 持有执行生命周期：页面断开不撤销仍有效的当前任务授权，也不批准新的权限；Host 重启、历史续接或创建分支不恢复旧的执行授权，不自动重启未知外部操作。

### 非聊天模型、记账与会话产物

- 分类与生图分别使用固定的能力模型绑定，调用前检查当前凭据、项目/任务许可与额度。调用入口覆盖实际 ModelRegistry 路径，不能只监听普通工具事件。
- 请求发出前记录额度预占与稳定身份；成功、错误、取消、缺回执和重启后按事实对账。父脚本、嵌套请求和汇总之间不重复收费或计数，缺失费用和部分覆盖明确显示。
- 请求结果中的用量与 SDK 价格估算保留来源、时间和模型身份；SDK 估算不称为实际账单。不能可靠核算单次费用上限时，必须走已同意的未知价格路径，不能冒称货币硬上限。
- 受支持的分类/生图能力和不可用原因在模型目录中可见；已有聊天账号及其配置继续可用，新增非聊天类型不静默改变账号归属或启用未选择的路由。
- 会话产物原子保存内容与来源关联，限制类型、大小和存储额度；部分输出、保存失败、磁盘不足、历史缺失均明确显示。下载不自动写入项目；写项目操作必须经过显式目标选择、路径及覆盖检查和单写协调。
- codemode 的跨调用状态按当前会话及分支来源恢复，额度与工具/模型授权不随状态或历史继承。数据保留与用户管理遵循既有材料/历史约定，不自动清理原件或静默扩大索引范围。

### 旧能力、历史与发行身份

- 既有账号隔离、受控工具、只读/编程模式、输入账本、即时补充/排队、未知 ACK 不重放、取消、续接及指定消息分支都进入 1.1.0 回归。
- Pi 新增的输入反馈、终止状态、耗时、上下文/历史条目按实际语义接入；稳定 inputId 和持久化账本继续承担 OMP 的关联与恢复职责。
- 旧历史和账号配置保留并验证新版读取/续接；遇到不兼容时保留原件，任何迁移可追溯。回滚时保留新版产生的数据，旧运行栈不能静默重写其不理解的历史。
- 新 Pi、传递依赖、内置工具和 WASM 等按实际内容进入候选栈合同、获取台账、SBOM/notices、包内容与安装验收。旧版本常量和既有补丁不能仅改字符串就声明兼容。
- 原材料链的生成、来源、构建和分发条件继续保留。开发依赖升级、兼容回归、材料通过、Full、真实服务和日常晋升是不同结果。

**当前接线缺口。** 10 月 9 日限定源码核验表明：输入模型虽携带材料 ID，当前生产准入、Pi 投递和草稿恢复仍按纯文本限制；现有用量累计不具备请求级去重与价格快照；资源配置 revision 固定为零，尚未贯通下一 worker；预览镜像、凭据代理及恢复主要是固定配方 PoC。对应工单须沿公开 Host、实际 Pi、持久化回读和 Ego Lite 页面取得证据，不能用禁用按钮、已有类型、局部计数器或 PoC 报告代替接入。历史目录展示投影可能截断正文，全文索引须核对原有效消息范围及 entry 定位。没有发现必须先单列的广域机械重构证据；必要局部整理随各完整切片完成，并保留原行为回归。

**新材料候选的生成与复验。** 优先复用材料 CLI 的公开输入/输出边界，补齐实际固定生成命令到材料校验的完整链路。每个需要新生成的对象在同一已固定环境中使用两个独立目录实际生成，完整输出集合与文件字节一致，并绑定输入、工具、配置、环境和输出身份；仅复制旧输出或先去掉未知字段再比较不能充当生成复现。新旧候选逐项差异有解释，文档覆盖、GIR 结构/接口、配置输出等本阶段可观察兼容性须通过；依赖真实 native 应用构建和 Pi/资源运行的兼容证明明确归 G2-00-04，不在材料报告中预写通过。非确定生成、未知转换或本阶段兼容性缺口保持 PARTIAL/BLOCKED。不同目标环境各自固定，不从单一环境推断跨平台通过。

**回归与完成标准。** Host 协议、生命周期、所有权、终端、人工入口和受影响 CLI 的既有回归继续适用；新增功能有对应正负路径。各批集成和 U6 晋升执行适用完整清单，纯文案修改使用内容/引用/格式检查。本次新功能仅形成规格，不制造其运行收据；此前有限开发依赖升级证据按顶部范围报告。

每组运行记录源码提交加工作树摘要、Pi/Node/stack/资源/输入身份、环境、命令与退出码、Task/Gate/证据层、脱敏证据及已知限制。使用 PASS/FAIL/NOT_RUN/BLOCKED；材料进度可为 PARTIAL/INCOMPLETE，但不能据此关闭必需出口。未知状态保留并回读；安全、身份、所有权或数据丢失失败阻断依赖批次。只有同一候选的必需层次全部满足才记通过；历史 FAIL/OPEN_UNATTRIBUTED 保留。真实 IME、物理故障、模拟触控和软件注入故障分别陈述，不互相补通过。
