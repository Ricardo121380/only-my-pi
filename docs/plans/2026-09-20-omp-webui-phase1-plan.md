# OMP 第一阶段详细开发计划：运行基线、只读 WebUI 与日常 CLI 升级

日期：2026-09-20。状态：第一阶段完成，M1-T 与 M1-I 均 PASS；日常安装已切换到 Pi 0.85.1，并完成回滚与同候选重新应用。证据、失败尝试及限制见[实施记录](2026-09-20-omp-webui-phase1-progress.md)。

本计划细化[三阶段总纲](2026-09-20-omp-webui-desktop-plan.md)。实际选择见[P1-Q1–Q9 决策记录](2026-09-20-omp-webui-phase1-discussion.md)；运行合同与晋升决策见[ADR-0017](../decisions/ADR-0017-versioned-runtime-contracts-and-stack-promotion.md)，术语以[CONTEXT.md](../../CONTEXT.md)为准。

## 1. 目标、范围与完成标准

本计划细化总纲的 **1A–1E**，增加最后的日常安装晋升环节 **1F**。已确认的总体架构仍为 **React + OMP Host + Pi RPC → Electron**。

第一阶段交付：

- 可通过 `omp web` 打开的中文三栏 WebUI。
- 自动汇总当前生效 Pi 会话目录中的历史项目，展示对话正文、工具摘要和按需展开的输出。
- 新建会话执行只读分析，支持模型选择、流式展示、取消及刷新重连。
- 只读文件树、文件预览、当前 Git diff 和 OMP 验证回执。
- 在隔离测试项目中，证明 GUI 审批、撤权、真实工具写入、账号隔离及跨进程协调可行。
- 将日常 OMP CLI 升级到经过验收的 Pi 0.85.1 候选栈，完成升级、回滚及重新应用演练。

M1 不开放旧会话续接、普通 GUI 写入、账号配置表单、文件保存或人工终端。这些仍属于第二阶段。

**“只读”指不修改项目文件；新会话历史、Host 索引及运行状态可以正常持久化。**

M1 分成两个完成点：

| 检查点 | 含义 |
| --- | --- |
| **M1-T：技术验收通过** | 候选运行栈、Host、只读 UI、技术探针及候选安装验证通过 |
| **M1-I：日常安装验收通过** | 日常 CLI 已切换、回滚到升级前栈、重新应用同一候选，并通过最终检查 |

两者都通过才算 M1 完成。仍沿用总纲“阶段必需门禁通过后自动继续”的约定。

## 2. 开发基线与架构决定

### 2.1 在当前目录开发，建立清洁源码基线

按用户选择，继续使用当前仓库目录，不新建 clone。

实施顺序：

1. 记录当前分支、HEAD、暂存区状态、所有相关 tracked/untracked 文件及内容摘要。
2. 核对现有安全修复、测试、类型文件和规划文档，避免只保存 `git diff` 而遗漏未跟踪文件。
3. 在当前目录创建第一阶段开发分支，保留现有工作内容。
4. 先通过相关回归，再形成明确范围的本地基线提交。
5. 后续按批次提交；不自动推送、创建发布或修改其他项目。

构建产物、临时项目及验收证据保存在源码目录之外。权威候选构建必须绑定清洁源码提交；开发期允许使用“HEAD＋工作树摘要”记录临时测试，但不能把它当最终产物身份。

讨论时源码分支为 `codex/preview-two-bilingual-readmes`、HEAD 为 `573ea9e1b844c27e19bbb4561ca902523a54bd23`，另有未提交安全修复和文档。实施前重新采集；本次文档落盘没有替代上述基线收口。

### 2.3 候选栈与扩展归属

讨论时 macOS builder 会复制旧 Pi seed，补丁选择又绑定旧产品版本。因此，升级工作必须覆盖构建和校验合同，不能只改开发依赖。[构建器](../../packages/distribution/package-builder.mjs)、[运行时补丁](../../packages/distribution/runtime-patches.mjs)

确定采用：

- 新旧版本化运行合同并存，保留旧栈校验与回滚能力。
- 候选记录精确 Node/Pi/扩展版本、包完整性、源码、产物树和补丁摘要。
- 外部扩展放入候选栈内的独立受控副本。
- 用户原外部包保持原样；不修改当前 PATH 中独立的 Homebrew `pi`。
- 已验证的补丁集合必须完整应用；未知输入摘要或缺失补丁均拒绝构建。
- 初始保持现有外部扩展版本，只有出现明确兼容失败时才调整对应包，并单独记录原因。

### 2.4 M1 模块边界

| 模块 | M1 职责 |
| --- | --- |
| Host 生命周期 | 单实例、启动、状态、退出、worker 回收 |
| 本机传输 | loopback HTTP/WebSocket、连接认证、版本协商、输入校验 |
| 受控 RPC worker | 复用运行栈和扩展加载约束，管理双向 JSONL、任务和取消 |
| 项目/会话目录 | Pi 历史项目索引、分页历史读取、OMP 回执关联 |
| 事件投影 | 快照、有序增量、重连、任务状态和脱敏错误 |
| 协调模块 | Host 单实例、会话占用；项目写入所有权合同与进程竞争探针 |
| 只读工作台 | 项目与历史、只读分析、文件/diff/回执三栏界面 |

后端沿用现有 Node ESM 与 Node 测试体系；共享合同采用 JSON Schema、现有 AJV 校验及 TypeScript 类型。前端使用 React、TypeScript、Vite，组件测试使用 Vitest 与 React Testing Library。

暂不迁移包管理器，不引入数据库或完整插件框架。新增代码必须显式纳入类型检查、测试发现和打包白名单，不能假定现有脚本会自动覆盖新目录。

## 3. 分批实施计划

### 1A：源码、环境与安全基线收口

**任务**

- 建立源码快照清单，区分已发布基线、当前未发布修复和新增 M1 内容。
- 核对真实运行环境、日常安装身份、current/LKG 指针及未完成事务。
- 验证当前 direct-Agent 安全修复，包括撤权、取消、补丁应用状态和真实工作区验证。
- 为新增 Host/UI 确定独立测试入口和产物位置。
- 完成本地基线提交，使后续候选构建具有清洁、可追溯来源。

**复用检查**

- 启动器、会话授权、workspace、managed-clone、orchestration、budget。
- writer-verification、project-gates/process、M12 integration/error paths、session composer。
- `lint`、`typecheck`、`schema:check`、`pack:check`、`agents:check`。

现有 lint 只覆盖 Git 跟踪文件，因此新增文件必须进入明确检查范围。

**交付物**：源码/环境基线、测试结果、变更清单、本地基线提交。

**退出条件**：相关安全回归无未解释失败，未跟踪文件没有遗漏，原有用户内容得到保留。

### 1B：Pi 0.85.1 候选运行栈与升级能力

**任务**

1. 更新并审核开发依赖锁，验证 Pi 公开 SDK/RPC 出口及扩展兼容。
2. 建立第一阶段候选合同，保留旧 M9/M10 合同和历史回执。
3. 增加 macOS 候选 staging 路径，从精确 Pi 包构建，不再借旧 seed 冒充新版本。
4. 构建栈内外部扩展副本，调整受控 loader，使其加载候选副本。
5. 将补丁选择改为按精确运行合同匹配，校验预期补丁集合。
6. 扩展 doctor、版本输出、manifest、ledger 和安装检查，能够识别旧栈与新候选。
7. 在隔离用户目录验证 Full 栈安装、启动、失败恢复和回滚。

**必须保留**

- 审核过的扩展顺序、资源过滤、工具白名单及权限模式。
- vendor 工具、许可证与补丁记录。
- 旧栈身份验证和回滚路径。
- 用户原外部包及日常配置。

**退出条件**：实际候选进程报告 Pi 0.85.1；完整受控扩展、安全补丁与隔离安装回滚通过。仅类型检查或 `package.json` 更新不算完成。

### 1C：Host、只读 worker 与数据接口

**启动与生命周期**

- `omp web`：启动或连接兼容 Host，并打开浏览器。
- `omp web status`：报告 Host、运行核心和活动任务状态。
- `omp web stop`：停止 Host 管理的任务并退出。
- 保留 `omp -- "web"` 的原任务文本含义。
- 只绑定 `127.0.0.1`，由系统分配空闲端口；endpoint 放在 OMP 私有状态目录。
- 同一数据目录只允许一个兼容 Host；版本不一致返回明确诊断，不另起冲突实例。

认证采用一次性浏览器配对，换取仅当前 Host 有效的会话。配对材料不进入日志或长期浏览器存储；HTTP 和 WebSocket 均校验身份、Host 与 Origin。验收使用 Host 同源提供的构建后前端。

**RPC worker**

- 复用现有受控启动构造，不直接调用会替换当前进程的 `launchDirectAgent()`。
- 使用独立子进程和双向 stdin/stdout，遵守 Pi 的 LF JSONL 分帧。
- 普通 M1 worker 保持 `read/grep/find/ls` 只读工具与既有权限约束。
- 不把任意 Pi RPC 命令、启动参数、扩展路径或权限位透传给浏览器。
- 显式选择已有可用模型，不修改 TUI 默认模型。
- 页面断开后只读任务继续；取消与 Host 退出须确认子进程结果，不能仅返回“已发送取消”。

**项目与历史**

- 初次索引汇总当前生效 Pi 会话根中的项目，后台增量加载。
- 不扫描整个用户目录，也不因发现项目而自动授予信任。
- 已删除项目保留历史入口并标记不可运行。
- 对话按需分页，工具输出延迟加载。
- 新任务创建新会话；旧会话只能查看，不续接、不改写。
- OMP 回执通过 session 与规范化项目身份关联，缺少关联时明确显示，而不是猜测。

**最小接口合同**

| 接口组 | 提供的能力 |
| --- | --- |
| Host | 状态、协议/运行身份、当前快照 |
| Projects | 列表、显式添加、可访问状态 |
| Sessions | 按项目列出、分页历史、新建只读会话 |
| Models | 脱敏可用模型列表 |
| Tasks | 开始只读任务、取消、查询状态 |
| Events | 快照后的有序增量、重连与缺口处理 |
| Inspector | 受限文件树、文件预览、只读 Git diff |
| Runs | 已关联的脱敏运行和验证回执 |

共享身份区分 `projectId`、Pi `sessionId`、本次 `taskId` 与可选 OMP `runId`，不把它们混用。事件携带 Host 实例身份及序号，任务命令具有请求去重标识。

Host 重启后清理失效连接，未结束任务标记为中断；不自动重发模型请求。回放只恢复显示，不重新执行任务。

**退出条件**：模拟 worker 和实际候选 RPC 均能完成新会话、流式输出、取消、重连和退出；公开接口不能取得项目写入能力。

### 1D：审批、账号与跨进程高风险验证

该批次提供测试能力，不给普通 WebUI 增加写入开关。

**审批与真实工具验证**

- 在专用临时 Git 项目中运行确定性模拟模型。
- 使用与未来 GUI 相同的内部审批适配，执行真实工具写入、撤权、取消和补丁状态检查。
- 保留 OMP 会话身份、审批代次和撤权后备校验。
- 受控宿主能力由 worker 启动过程建立，不能由 HTTP/RPC 请求自报。
- 普通 RPC、普通 M1 WebUI、伪造权限参数均不能进入该测试路径。

**账号隔离验证**

- 两个同 Provider 测试账号使用不同模拟凭据与存储。
- 验证各自请求使用正确身份，不能回退到默认账号或环境凭据。
- 验证同账号并发刷新、账号切换前停止 worker、凭据已存但同步失败。
- 使用 Pi 公开 `ModelRuntime` 与服务注入接口；不复制真实用户 token。

**协调验证**

- Host 单实例竞争。
- 同一会话重复占用。
- CLI/GUI 项目所有权竞争及路径别名。
- 进程崩溃、PID 复用或无法确认所有者时拒绝错误抢占。
- 取消与补丁应用交错时保留 `APPLICATION_UNKNOWN`。

**退出条件**：真实进程边界和工具执行证明这些合同成立；不能仅依靠 mock 一个成功审批回调通过。

### 1E：中文三栏只读工作台

**界面范围**

- 左栏：项目、历史会话、新建只读分析。
- 中栏：历史正文、实时输出、工具摘要、模型选择、取消与连接状态。
- 右栏：文件树、文件预览、当前 Git diff、运行与验证回执。

**交互与安全**

- 旧会话明确标为只读历史，发起任务会新建会话。
- 未加载、空数据、错误、取消中、重连及项目失效均有独立状态。
- Markdown 不执行原始 HTML；不自动加载不受控远程资源。
- 文件接口限定在所选项目范围，校验真实路径及符号链接边界。
- Git diff 使用明确参数调用，不执行仓库自定义 diff/textconv 命令。
- 长会话虚拟化或分页，工具输出限制单次传输量。
- 覆盖中文输入法、键盘导航、焦点恢复和窄窗口侧栏折叠。

**设计辅助**

向 Open Design/K3 提供脱敏设计简报和模拟数据，核实模型身份后使用。不可用则明确记录，由当前 Codex 完成设计。设计需形成组件状态与交互规则，不能只交付效果图。

**退出条件**：构建、前端类型检查、组件测试和 ego-browser 真实操作通过；M1-T 聚合验收通过。

### 1F：日常 CLI 升级、回滚与重新应用

该环节只在 M1-T 通过后执行。

**切换前**

- 固定源码提交、候选 archive 摘要、stackId、协议及补丁身份。
- 重新核验日常 active 栈；如果它已改变，停止切换并重新绑定升级基线。
- 完整验真本次旧栈，准备独立保存的候选管理器、候选包与回滚材料。
- 只结束本次验收创建的进程。存在用户正在使用的相关 Pi/OMP 会话时，保持“待切换”，不强停。

**操作顺序**

1. 使用已支持新旧合同的候选管理器执行 Full 栈 update 预检。
2. 将日常安装切换到已验收候选。
3. 从 PATH 中真实 `omp` 核验 source、stack、Pi、Node 与只读 WebUI。
4. 显式回滚到本次切换前的 active 栈。
5. 验证入口、受管配置、外部包归属和历史仍正常。
6. 重新应用同一个不可变候选。
7. 执行最终 smoke 和安装态真实任务。

候选管理器与包必须位于可能被回滚删除的栈目录之外。不能用普通 Harness rollback 替代完整 stack rollback，也不把这次升级改成渠道迁移。[Full 栈事务](../../packages/release-stack/stack-transaction.mjs)

凭据与会话属于用户数据，升级回滚不得用旧副本覆盖合法的新 token 或新历史；正常运行产生的变化与安装事务变化分开记录。

**退出条件**：M1-I 通过，日常安装最终停留在经过验证的候选栈。任一步失败，停止后续阶段并恢复到最后验证过的栈。

## 4. 测试矩阵、证据与门禁

### 4.1 分层验收

| 门禁 | 主要内容 | 类型 |
| --- | --- | --- |
| **P1-A** | 清洁源码、环境身份、现有安全回归 | 离线 |
| **P1-B** | 新旧合同、候选构建、补丁完整性、隔离安装回滚 | 隔离集成 |
| **P1-C** | Host 认证、RPC、快照/事件、取消和进程退出 | 模拟＋真实无模型进程 |
| **P1-D** | 审批、真实工具写入、账号隔离、所有权竞争 | 临时项目＋模拟模型 |
| **P1-E** | Web 构建、组件、历史/文件/diff、浏览器操作 | 前端与浏览器 |
| **P1-L** | 有界真实模型任务 | 现有模型路由 |
| **P1-I** | 日常切换、回滚、同候选重新应用 | 真实安装 |

新增专用第一阶段聚合门禁。现有 M12 结果只作为相关回归依据，不改写旧 M9/M10 收据，也不把 `DETERMINISTIC_PASS_PROTECTED_PENDING` 当完整通过。

P1-L 的前两项候选任务纳入 M1-T；第三项最终安装态任务纳入 M1-I。不能要求 M1-T 提前包含尚未执行的日常晋升结果，也不能在第三项缺失时给完整 P1-L 标记 PASS。

### 4.2 必测失败场景

- 未认证请求、异常 Origin/Host、过期配对、协议不兼容。
- 假 worker 身份、畸形 JSONL、超大输出、断线与重连缺口。
- 同请求重复提交、Host 崩溃后前端重试造成重复模型调用。
- 普通 UI 伪造写入、Bash、权限、扩展或账号存储参数。
- 迟到审批、撤权与工具开始竞态、取消期间结果到达。
- 同 Provider 两账号串用、隐含凭据回退及刷新冲突。
- 历史损坏、项目已删除、关联回执缺失、文件越界。
- 候选实际仍运行旧 Pi、补丁缺失、旧栈校验失效。
- 用户外部扩展被意外覆盖、升级中断、回滚目标错误。
- Host 退出后子进程遗留或活动所有者被错误抢占。

### 4.3 真实模型预算

保持整个 M1 **最多 3 个小型任务＋1 次失败重试**，不按批次重新计数：

1. 候选 WebUI：在临时项目完成只读分析及流式展示。
2. 候选 WebUI：取消一个只读任务，检查 UI 与后端终态。
3. 最终安装态 CLI：在临时项目完成一次小型修改与检查，确认升级后的既有 TUI 编程能力。

审批竞态、多账号和复杂 writer 分支使用模拟模型覆盖，避免耗尽真实验收预算。回滚与重装本身使用无模型检查。

只有实际完成的 Provider 路径才能记录真实互操作通过；其他路径保留模拟覆盖说明。沿用既有模型路由，不开通新服务；没有可用额度或身份时相应必需项保持未完成。

### 4.4 性能与证据

使用固定验收机，记录硬件、运行核心与测试样本：

- 10,000 条事件、5MB 工具输出及长 diff。
- 本地输入回显 P95 目标低于 100ms。
- 取消本地确认 P95 目标低于 500ms，进程实际退出另记。
- 记录初次项目索引、历史首屏、冷启动和完整进程树内存。

每组证据记录 source、candidateId、命令、结果、截图、调用次数和限制。状态统一使用 `PASS / FAIL / NOT_RUN`。

`ego-browser` 不可用、真实验收额度不足或必需检查失败时，相应门禁不能标为通过。性能数值是验收目标，不是已经测得的结果。
