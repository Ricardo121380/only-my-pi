## What to build

用户明确批准 MCP 对当前项目的写入后，工具实际修改指定文件并返回可核对的结果；无所有权、越界和并发冲突被拒绝。

## Acceptance criteria

- [ ] 从审批到执行同时核对工具许可、编程授权、当前项目写入所有者及服务器进程范围，任何一项缺失时真实文件不改变。
- [ ] 本地服务器启动本身纳入隔离；路径/链接/环境/凭据限制可在真实子进程验证，不能仅拦 MCP 请求后假定进程不会自行写入。无法落实边界的服务器明确拒绝项目写入准入。
- [ ] 工具名、Schema 或目标变更使旧授权失效；多工具/多入口竞争保持项目单写，CLI、人工终端、Agent 和 MCP 不同时写入。
- [ ] 记录任务/父调用/工具/目标及结果身份；已修改但回执丢失保持未知，不自动重试或撤销用户文件，也不伪称验证通过。
- [ ] 用受控服务器的接收账本和实际文件效果验证正例、跨目录/链接逃逸、撤销竞态、取消、崩溃和残留；页面显示拒绝原因及已发生/未知结果。
- [ ] 覆盖 macOS 当前产品目标和现有 CLI 的适用权限合同，保留受影响所有权/终端回归；无经过验证的隔离实现则本票保持未完成。
- [ ] 保存实际源码/工作树、Pi/Node/候选与输入身份、命令/退出码、失败及限制，分列 Standards 与 Spec。未运行或缺必需证据不记 PASS；实际服务、付费、安装切换另按具体任务授权。
