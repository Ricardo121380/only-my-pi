# OMP 第一阶段开发计划讨论记录

日期：2026-09-20。状态：讨论已收敛，用户已确认共同理解；文档已落盘，产品实施与阶段验收尚未开始。

本轮使用 grill-with-docs 的 grilling 与 domain-modeling 流程，针对[总体计划](2026-09-20-omp-webui-desktop-plan.md)的第一阶段细化。已确认的总体产品决策继续有效；本轮新增或细化的第一阶段范围见下表。实施入口为[第一阶段详细计划](2026-09-20-omp-webui-phase1-plan.md)。

## 设计决策树

```text
第一阶段 1A–1E（总纲已接受）
├─ 可用产品：历史 + 新建只读分析（P1-Q1）
│  ├─ 汇总当前 Pi 会话根内全部历史项目（P1-Q5）
│  ├─ 旧历史只读，新会话执行（P1-Q6）
│  ├─ 对话正文、工具摘要和按需展开输出（P1-Q7）
│  └─ 文件预览 + Git diff + 验证回执（P1-Q8）
├─ 开发位置：沿用当前目录并形成核对过的本地基线（P1-Q3）
├─ 高风险验证：临时 Git 项目中的真实工具写入（P1-Q4）
└─ 升级：候选通过后同时升级日常 CLI（P1-Q2）
   ├─ 外部扩展使用栈内独立受控副本（P1-Q9）
   └─ M1-T 技术通过 → 1F 日常切换/回滚/重新应用 → M1-I
```

## P1-Q1–Q9 最终选择

| 编号 | 决策 | 用户实际选择与约束 |
| --- | --- | --- |
| P1-Q1 | 一期可用能力 | 历史＋只读分析；可选择真实项目、查看历史、发起新任务并观察流式过程和取消结果 |
| P1-Q2 | Pi 升级影响范围 | 同时升级日常 CLI；在候选验收之后执行真实安装与回滚验证 |
| P1-Q3 | 开发隔离 | 沿用当前目录；核对现有修改并形成本地基线提交，不新建 clone |
| P1-Q4 | 受控写入试验 | 专用临时 Git 项目真实验证；确定性模拟模型驱动工具写入、撤权、取消和补丁状态，普通 UI 始终只读 |
| P1-Q5 | 项目发现 | 汇总全部 Pi 项目；范围是当前生效 Pi 会话目录，不扫描整个用户目录 |
| P1-Q6 | 一期会话续接 | 旧历史只读、新建会话执行；旧 CLI 会话的停止后续接留到第二阶段 |
| P1-Q7 | 历史呈现 | 对话正文与工具摘要；工具输出按需展开并限制单次加载量 |
| P1-Q8 | 一期右侧面板 | 文件预览＋Git diff＋回执；保存和人工终端仍在第二阶段 |
| P1-Q9 | 外部扩展归属 | 栈内独立受控副本；保留用户原包与独立 raw Pi，副本随候选栈验证、升级和回滚 |

## 共同理解确认

在九项选择完成后，向用户汇总了：沿用当前目录、自动汇总 Pi 历史、新建只读分析、临时项目技术验证，以及技术通过后的日常安装切换/回滚/重新应用。用户选择“准确，生成详细计划”。

相应完成标准拆分为 **M1-T 技术验收**和 **M1-I 日常安装验收**，二者均通过才算第一阶段完成。有用户任务仍在运行时暂停安装切换，不强行结束这些任务。阶段必需门禁通过后自动推进的总纲约定不变。

## 术语澄清

- “只读”限制项目文件修改，不禁止保存新会话历史和 Host 元数据。
- “候选升级通过”不等于日常 CLI 已升级；需要单独完成安装晋升。
- “升级前栈”是本次切换前的 active，不可用更早的 LKG 代替。
- “栈内副本”与用户原包分开管理，不代表接管或覆盖用户原包。
- 本轮临时项目写入探针不是普通 WebUI 的产品写入功能。

规范定义已同步到[领域词汇表](../../CONTEXT.md)。

## 核验事实与后续验证

| 讨论时已核实的事实 | 对计划的影响 |
| --- | --- |
| 当前日常 OMP 是 legacy Full 栈，Pi 0.84.3、嵌入 Node 24.19.0，并非 README 所述 npm/native 安装 | 沿用 Full 栈事务，不以 npm install 替代升级 |
| macOS builder 复制旧 Pi seed，补丁选择有旧产品版本限制 | 必须构建真实新候选并证明补丁集合完整 |
| 九个外部包是用户目录中的借用包 | 新候选建立栈内副本，原包内容保持不变 |
| 正式候选构建和权威门禁要求清洁源码，当前含未提交修复与文档 | 1A 先核对并形成可追溯本地基线 |
| 产品 Host、浏览器事件投影及 React 工具链尚未建立 | 新增对应模块和测试，不能借用旧 PASS |
| run 记录、Pi 会话和 ledger 是不同对象 | Host 建立目录及明确关联，不把 sessionId、taskId、runId 混用 |

以上来自只读源码与非秘密安装身份核验；本轮没有安装候选、读取真实凭据、启动模型任务或运行阶段验收。执行时需重新核对当前事实。

## 延续的约束

- M1 使用既有模型路由，整个阶段最多 3 个小型真实任务＋1 次失败重试；复杂安全与账号探针使用模拟模型。
- ego-browser 用于前端操作验收，不可用时相关门禁保持未完成。
- K3 是可选设计辅助；先核实实际入口和模型，不可用时说明并由当前 Codex 继续。
- 阶段二的完整账号表单、普通 GUI 编程、编辑保存和人工终端，不提前混入第一阶段。
- 当前请求仅要求文档落盘；基线提交、代码实现、运行时升级和安装晋升均尚未执行。
