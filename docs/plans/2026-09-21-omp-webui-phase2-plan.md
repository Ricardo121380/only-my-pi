## 2A 详细工作单

现状：`packages/host/models.mjs` 启动独立目录 worker；`models-worker.mjs` 使用 configRoot 下的 auth.json/models.json。因此当前 Models 接口是 CLI 模型目录，不是 GUI 多账号管理。

### 2A-1：账号目录与公开合同

- 在 Host 私有状态目录下管理 GUI 自有账号；服务端生成 accountId，禁止客户端提交凭据存储路径。
- 目录元数据只保存 accountId、原始 providerId、显示名称、认证类型及脱敏状态；秘密使用 Pi 公共凭据存储，不进入目录响应。
- CLI 账号标记为只读引用，GUI 更新、删除、登出接口明确拒绝对其操作。
- 定义列表、创建、配置、认证状态、删除及绑定请求的输入 Schema、错误码和客户端类型。协议变化同步版本协商；旧客户端不得误发新能力。
- 存储使用现有原子写入方式和私有目录权限；验证并发更新、损坏文件、未知 ID、路径注入与失败恢复。
- 验收：同 Provider 两条独立身份；响应无 Key/token；CLI 配置未改；越界输入被拒。

### 2A-2：账号对应的 ModelRuntime 与 worker

- 每账号独立 authPath/modelsPath/modelsStorePath，通过固定版本公开 ModelRuntime 创建。
- 在服务端为任务解析显式绑定；浏览器不得透传环境变量、扩展路径或任意启动参数。
- 保留受控扩展、安全策略与共享历史根，只隔离模型身份。检查环境凭据、默认账号和模型目录的回退路径并拒绝隐式回退。
- 账号被活动任务占用时拒绝切换、删除、登出；停止并确认进程退出后才能更换，重建 worker，不恢复旧编程授权。
- 验收：模拟服务检查实际请求身份，而非只断言构造参数；缺失/失效账号、额度错误不能换账号。

### 2A-3：认证与静态 Provider

- API Key 通过已认证的本机接口提交；不回传、不持久化到浏览器、不记日志。错误输出采用允许字段列表。
- OAuth 仅展示运行时支持的 Provider，串行登录，支持取消与超时；复用 Pi 公共交互合同，不自建认证协议。
- 区分认证失败、凭据已保存但模型同步失败；并发刷新沿用运行时锁。
- 自定义 Provider 仅允许经过验证的静态配置；拒绝任意配置命令与代码执行字段。
- 验收：模拟 OAuth 成功/拒绝/取消/刷新冲突；网络错误不泄露原始凭据；真实互操作只声明实际测过的 Provider。

### 2A-4：Glacier 界面接入

- 在现有设置弹窗内增加账号管理入口，模型选择关联明确账号；保留页面结构和视觉资源。
- 覆盖空目录、加载、错误、凭据已存但同步失败、账号占用、确认删除和缺失绑定。
- 历史绑定不含秘密；新任务必须显式选择；历史没有绑定时要求选择，不能从模型名猜测。
- 中文输入法、键盘焦点与 Escape、390/761/1440px 布局均检查；不自动执行真实任务。
- 验收：服务端集成、组件测试与 Ego Lite 完整账号流程通过。仅表单可用不能给 2A PASS。

## 2B–2F 实施接缝

- 2B：复用 interaction/受控运行时探针；先落实 worker 最终授权判断，再开放前端审批。执行、应用与真实验证是三个独立事实。
- 2C：先接入所有写入口及会话占用，再允许续接；重连采用快照与有序事件，不重放写命令。Host 崩溃不得凭超时认定进程已退出。
- 2D：读取版本摘要作为保存前置条件；外部改动要求重新读取/合并，不强制覆盖。离开手动模式先处理脏标签。
- 2E：PTY 包在实施时核实精确版本、原生模块与运行时兼容；进程树身份和回收失败必须可诊断，不把关闭 UI 当关闭终端。
- 2F：固定 10,000 事件、5MB 输出与长 diff 样本；输入 P95 <100ms、取消本地确认 P95 <500ms；进程退出另记。记录冷启动和进程树内存，不宣称跨设备 SLA。
