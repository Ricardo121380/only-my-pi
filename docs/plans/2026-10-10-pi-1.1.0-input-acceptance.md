## 实际改变

Host 保持先持久化输入意图和稳定 inputId，再调用 Pi。原生 RPC prompt 的 disposition 标明来源 `pi-prompt`；自定义输入桥接的反馈标明 `omp-custom-message`，表示 SDK 调用路径的 started/queued，不能冒充原生 prompt 返回。两类反馈均不构成消费证明；消费只来自同一分支的持久 carrier、inputId 与内容摘要。丢失 ACK 后只读 lookup 所得反馈也会保存，不重新调用 deliver。

任务记录 assistant/tool durationMs、stopReason 和终止 aborted。Pi 自行终止且无 Host cancel 时仍落为 cancelled，并暂停未投递队列。handled prompt 不等待不会出现的 agent_settled，也不生成消费回执。未知结果、worker/Host 中断继续保守暂停，原受控任务恢复不重新授予权限。

新 `session-history` 边界在交给 Pi 前校验文件、版本、条目类型与树关系，用规范 SessionManager 在内存迁移和构建上下文。Host 历史保留原会话消息，同时单独返回新版 context 投影和 usage 元数据；carrier 核对读取规范原始分支。损坏或未知类型明确拒绝且保留原件。获准续接旧格式之前，完整原字节存入 configRoot 下 `only-my-pi/history-backups`，备份不进入可执行历史发现。

既有公开会话 runtime 的 `fork(entryId, { position: "at" })` 包含选定条目，取得新身份，保留源历史字节；新分支不携带旧执行队列和写入授权。新增 WebUI 位置分支仍由 #43 交付。
