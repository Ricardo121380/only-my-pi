# Pi 1.1.0 升级后适配讨论

开始日期：2026-10-09；最近更新：2026-10-10。状态：grill-with-docs 已完成，Q13 已确认；开发依赖已升级；to-spec 已发布并回读；Q14 已确认，to-tickets 已发布并回读；完整适配尚未实施。

**已确认方向**

- D0：用户明确要求直接升级现有开发基线至 Pi 1.1.0，然后重新 grill-with-docs，确认后继续 to-spec 和 to-tickets。此前[影响评估](../compatibility/2026-10-09-pi-1.1.0-impact-assessment.md)提出的“先保留 0.85.1 开发目标、建立独立迁移候选”建议由本决定替代。
- Q1：本轮同时接入 MCP 与 codemode，扩大规格和验收范围；不是只做既有能力的等价迁移。
- Q2：本轮关闭缓存保温，未来另行接入。
- Q3：TUI 默认 fullscreen，保留 regular 选项；此选择不改变 WebUI Glacier 布局。
- Q4：MCP 本轮同时支持本地 stdio 与远程 Streamable HTTP，分工单交付；实际启动服务器、联网和登录仍需显式启用。
- Q5：OMP 独立管理 MCP 服务器配置、凭据引用和项目覆盖，CLI/TUI 与 WebUI 使用同一套受控配置；支持显式导入既有 Pi 配置，不自动读取并启动其中的服务器，不改写 raw Pi 原配置。
- Q6：codemode 本轮同时支持分类和图片生成，完整纳入显式模型选择、授权、预算与用量，而非推迟到后续阶段。
- Q7：服务器启用与工具调用分开授权。MCP 与 codemode 的每个嵌套工具调用均检查当前权限；未授权工具首次使用时确认，可选择仅本次或当前任务有效。工具定义或目标变化、任务结束后重新确认，不以服务器自报的“只读”作为自动放行依据。
- Q8：按项目分别明确选择分类和生图的 OMP 账号与模型，在任务启动时固定绑定；未配置的能力禁用，不随聊天模型切换自动更换，也不允许脚本切换到其他账号或模型。
- Q9：任务启用前明确分类/生图的次数、并发、输入与输出额度；能可靠核算单次上限时预占费用预算，不能核算时提示未知价格，并须明确同意按其他额度运行。预算不足即停止，已发出但结果未知的请求继续占额，不自动重试或扩额。
- Q10：MCP 本轮支持受控项目写入，同时要求工具授权与当前项目写入所有权；本地服务器必须满足受控进程、路径及凭据隔离，无法满足则拒绝。服务器启用不授予项目写入权，codemode 并行调用不绕过单写规则。
- Q11：CLI/TUI 与 WebUI 均交付分类/生图调用状态、结果和用量；生成图片作为会话产物保存，可查看、下载和历史恢复。写入项目文件须明确选择并经过写入检查。
- Q12：Pi 1.1.0 兼容与不依赖 parser 的 MCP/codemode 切片先行，材料链独立继续；使用 parser 的能力保留 G2 依赖，最终在完整安装验收汇合。沿用总规格 #19 与既有 #20–#61，只新增缺少的工单，保留原 U2–U6 阶段出口。
- Q13：用户确认完整成稿共识及最高测试边界，进入 to-spec 更新 #19，随后继续 to-tickets 提供完整拆分与依赖草案审阅。
- Q14：用户答复“按完整稿发布并更新依赖（推荐）”，批准新增 14 张、补充 18 张既有工单、保留其余 24 张正文与原 50 条依赖，并增加 19 条新路线内部边及 4 条新旧连接边；父规格 #19 保持不变。
- 开发基线与能力范围已记入 [ADR-0019](../decisions/ADR-0019-pi-1.1-development-baseline-and-native-tools.md)，具体授权与预算选择记录于本讨论；相关术语同步至 [CONTEXT](../../CONTEXT.md)。历史证据保留；完整新版本验收仍由实际运行产生。

**接入点核查（2026-10-10，只读事实）**

固定上游 v1.1.0 源码核查，不是新能力运行通过证据：

- codemode 普通工具调用经 `ctx.executeTool`，保留 `tool_call` / `tool_result` 和 `parentToolCallId`；直接 `models.classify` / `models.generateImages` 调用 `ModelRegistry`，不经过相同工具钩子。OMP 必须为模型调用另接授权、账号绑定、预算与完整回执，不能只审批父 codemode 工具。来源：上游 `packages/coding-agent/src/extensions/codemode/execute.ts:462,481,715–730`。
- codemode 的输出 token 上限不是模型费用上限；上游脚本默认无超时，模型并发限制仅作用于单次脚本。现有结果提供模型、状态、耗时及可选费用，不能据此证明取消后远端已停止或费用为零。来源：上游 `codemode/execute.ts:50,245–248,484–485,675–693`。
- MCP 可通过 `loadConfig`、`credentials`、`createTransport`、`updateConfig` 等公开参数接入 OMP；默认仍会合并扩展注册的服务器，并在会话启动后连接启用项。配置接管必须同时处理注册来源和启动准入。来源：上游 `packages/coding-agent/src/extensions/mcp/index.ts:69–91,345–362,1111–1138`。
- MCP 的默认认证键包含服务器名与 URL，不包含项目身份；env、headers 与 OAuth client secret 支持动态解析，不能把导入配置直接视为已获准执行命令。工具作者的 `readOnlyHint` 等注解不是已验证权限事实。来源：上游 `mcp/oauth.ts:130–167`、`mcp/runtime.ts:98–121,238–246`、`core/extensions/types.ts:518–524`。
- 上述公开接点支持继续设计受控接入；尚未证明所有隔离、逐请求审计和预算行为已实现或通过测试。子代理核查与主代理关键调用点抽查分属静态证据。
