## 2. 执行约束与可观察行为

以下设计约束已由 Q13 确认；它们不授权本次直接运行用户 MCP、调用付费模型或切换日常安装。

### MCP 配置、身份与启动

- 新建或导入后展示连接目标、启动命令、能力和配置来源，由用户明确启用；导入不执行命令、不登录、不启动服务器，也不改写原配置。
- 全局默认与项目覆盖使用可追溯的配置版本。任务固定其已选择的配置；修改进入后续任务，当前任务不悄悄换目标或扩大权限。撤销授权、停用或凭据失效应阻止后续调用，已发请求如实结算。
- 配置文件、扩展注册、内置发现及 direct/deferred/codemode 等暴露方式都受同一准入规则约束；工具是否向模型展示与能否调用分别判断，不能靠隐藏工具维持权限边界。
- 秘密通过 OMP 管理的凭据引用取得，不交给脚本、聊天历史、公开状态或日志；不同项目/连接的身份绑定必须可区分。显式复用凭据引用不授予新的工具权限；覆盖目标后不沿用旧目标的登录或授权。
- 远程连接包含显式认证/登录、取消登录、失效与撤销流程；本地服务器采用有限环境和可确认的进程生命周期。导入中的动态命令取密、环境继承或 Provider 认证转借，须转换为受控配置或明确拒绝，不能自动执行。
- 读取 MCP 资源同样检查授权、目标和返回大小；不把远端 HTML 或 MCP Apps 变成新的可执行页面。服务声明的只读、幂等及破坏性注解只作展示依据，不替代 OMP 的实际权限判断。

### 工具、编程授权与取消

- codemode 的父工具授权不代替嵌套调用检查。MCP 写入当前项目，须同时满足工具授权、编程授权及当前任务持有的项目写入所有权；只读任务不能借外部工具写入项目。
- 本地服务器的启动本身可能产生副作用，必须经过受控启动准入和路径/凭据隔离；无法落实隔离的连接不获得该项目的写入准入。并发调用中，项目写入按原单写规则协调，不能仅用工具名称或服务器提示分类。
- 每次执行有有限的时长、并发、输入/输出和结果存储额度；脚本不能扩大 Host 所允许的额度。适用具体上限进入可验证配置和工单验收，不使用无限默认值。
- 已发调用具有稳定身份，关联任务、父脚本、服务器/模型、配置版本及授权范围。取消阻止新调用、撤销待处理审批和排队工作，并对已发调用及进程残留核对结果。
- 脚本失败或取消不撤销已产生的外部副作用；已完成、失败、取消请求和结果未知分别呈现。不自动重放结果未知的写入或模型请求，不把本地取消确认称为远端已停止或零费用。
- 延续 Host 持有执行生命周期：页面断开不撤销仍有效的当前任务授权，也不批准新的权限；Host 重启、历史续接或创建分支不恢复旧的执行授权，不自动重启未知外部操作。

### 非聊天模型、记账与会话产物

- 分类与生图分别使用固定的能力模型绑定，调用前检查当前凭据、项目/任务许可与额度。调用入口覆盖实际 ModelRegistry 路径，不能只监听普通工具事件。
- 请求发出前记录额度预占与稳定身份；成功、错误、取消、缺回执和重启后按事实对账。父脚本、嵌套请求和汇总之间不重复收费或计数，缺失费用和部分覆盖明确显示。
- 请求结果中的用量与 SDK 价格估算保留来源、时间和模型身份；SDK 估算不称为实际账单。不能可靠核算单次费用上限时，必须走已同意的未知价格路径，不能冒称货币硬上限。
- 受支持的分类/生图能力和不可用原因在模型目录中可见；已有聊天账号及其配置继续可用，新增非聊天类型不静默改变账号归属或启用未选择的路由。
- 会话产物原子保存内容与来源关联，限制类型、大小和存储额度；部分输出、保存失败、磁盘不足、历史缺失均明确显示。下载不自动写入项目；写项目操作必须经过显式目标选择、路径及覆盖检查和单写协调。
- codemode 的跨调用状态按当前会话及分支来源恢复，额度与工具/模型授权不随状态或历史继承。数据保留与用户管理遵循既有材料/历史约定，不自动清理原件或静默扩大索引范围。

### 旧能力、历史与发行身份

- 既有账号隔离、受控工具、只读/编程模式、输入账本、即时补充/排队、未知 ACK 不重放、取消、续接及指定消息分支都进入 1.1.0 回归。
- Pi 新增的输入反馈、终止状态、耗时、上下文/历史条目按实际语义接入；稳定 inputId 和持久化账本继续承担 OMP 的关联与恢复职责。
- 旧历史和账号配置保留并验证新版读取/续接；遇到不兼容时保留原件，任何迁移可追溯。回滚时保留新版产生的数据，旧运行栈不能静默重写其不理解的历史。
- 新 Pi、传递依赖、内置工具和 WASM 等按实际内容进入候选栈合同、获取台账、SBOM/notices、包内容与安装验收。旧版本常量和既有补丁不能仅改字符串就声明兼容。
- 原材料链的生成、来源、构建和分发条件继续保留。开发依赖升级、兼容回归、材料通过、Full、真实服务和日常晋升是不同结果。

## 3. 最高测试接口与分层证据

尽量沿已有公开入口证明外部行为，局部单测补充边界；不以私有 helper 返回或模拟事件代替完整链路。以下是设计，尚未执行的新检查记为 NOT_RUN。

| 范围 | 主要验收路径 | 必须观察到的事实 |
| --- | --- | --- |
| Pi 等价适配 | 公开 Host/CLI → 实际 Pi 1.1.0 worker → 本地受控模型服务；支持的 Node 22.19.0 / 24.19.0 矩阵 | 账号与历史归属、输入消费、权限、取消与恢复；独立计数证明缓存保温没有额外模型请求；不能只改测试版本断言 |
| MCP stdio | 真实配置/启用入口 → 受控子进程 → 真实协议交互与确定性工具 | 调用接收数、真实文件效果、拒绝时零执行；导入不启动、越界/凭据泄漏负例、进程组退出及残留阻断 |
| MCP HTTP | 真实配置/登录入口 → Pi MCP → 本地受控 Streamable HTTP/OAuth 服务 | 目标与凭据隔离、取消登录、失效/撤销、工具更新、明确授权、断连未知结果和无写入重放；不使用外部真实账号 |
| codemode | Host/CLI → 实际 Pi + QuickJS → 嵌套工具/MCP | 每个子调用进入当前策略；直接/隐藏/延期发现不绕过权限；并发写入不冲突；超时、取消、部分成功与重启不会重放 |
| 分类/生图 | 公开任务入口 → 实际 Pi 非聊天模型调用 → 本地受控 Provider 协议服务 | 实际账号/模型、请求接收数、预算预占/超额拒绝、未知结算及重启去重；合法分类结果/图片真实到达产品，不仅验证帮助函数 |
| 产品交互 | Ego Lite 实际 WebUI 旅程；实际 CLI/PTY 核验 fullscreen 与 regular | 配置→授权→执行→结果→用量→历史→下载/显式写入；禁用、等待、失败、断连和拒绝可解释；Glacier 与现有终端保持 |
| 最终候选 | 精确干净源码身份 → 默认发行入口 → 隔离 Full 安装、回滚及重新应用 | 包内完整依赖与身份、无开发/全局回退、原材料门禁、旧账号/历史及新会话产物保留；日常晋升单独验收 |
| 真实外部服务 | 明确新增授权后，选定真实 MCP 服务与分类/生图 Provider 做小型有界场景 | 实际路由、服务接收、结果与费用来源相符；预算与取消限制如实记录，不把本地受控服务当真实 Provider 通过 |

真实服务用量和数据外发不由本稿自动授权；在执行对应工单前提供具体服务、输入、操作和预算。原真实 Provider 验收包须随新增能力更新建议范围，但不挪用已耗尽历史预算。

## 4. 规格与工单组织

- 更新现有总规格 #19，保留既有需求 ID、Task ID、Gate、历史证据和 #20–#61 身份；新增 Pi/MCP/codemode 需求单列，44 仅是原 WebUI 产品任务分母，不伪装成扩大后仍然完整的总分母。
- 兼容基础回归及无 parser 依赖的新切片可以先行；需要 parser 的动作继续绑定 G2。原 U2–U6 阶段出口保留，最终 U6/完整安装加入新能力，不用开发 PASS 替代材料或发行门禁。
- 新工单按可观察的完整用户动作拆分，并覆盖自己的配置、执行、持久化、UI/CLI 和必要拒绝路径；不会按数据库/API/页面横向切成不可独立验收的层。
- MCP stdio/HTTP、codemode 工具组合、分类、图片生成分别具有可核对的交付出口；用量/配置等共有职责与既有 #46–#52 明确衔接，避免新旧两套重复实现。
- to-spec 在 Q13 后综合并发布总规格；随后 to-tickets 提交完整编号草案和依赖供审阅，确认后才创建/更新实际工单及原生依赖，并回读验证。不得把父规格发布直接当作拆票方案已批准。

## 5. 本轮范围外与当前证据

本轮不接入缓存保温、虚拟模型自动路由、旧 SSE、MCP Apps 可执行页面，也不增加未经选择的通用插件市场或远程多用户服务。原 WebUI 全部已选范围仍保留。

截至当前，实际完成的是开发依赖升级和有限验证：四组类型检查、真实 Pi 的本地账号 RPC 夹具、隔离 CLI `--version`。MCP/codemode 新能力及完整新版验收尚未实施，不新增产品 Gate PASS。原工作树保留；实际构建、安装切换、外部服务、付费调用和公开软件发行分别遵守对应任务授权。
