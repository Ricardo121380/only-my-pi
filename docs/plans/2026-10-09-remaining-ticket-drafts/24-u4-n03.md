## What to build

用户能分别查看主 Agent、子 Agent、分支继承和新消费，汇总既不漏掉受支持来源，也不重复计入历史。

## Acceptance criteria

- [ ] 将受支持子 Agent 的实际请求/工具回执连接到稳定父任务与会话 lineage，页面可展开主子明细及覆盖范围。
- [ ] 同一子任务回执重复、晚到、失败或取消时按请求身份去重，未知父关联显式保留，不按汇总差额猜消费。
- [ ] 分支已继承历史与分支创建后实际请求分别展示；原会话、多个分支及共享请求来源不重复累计。
- [ ] 保留各请求的缓存语义、币种/价格快照、部分和真实零值；不同覆盖范围不能以单一总数掩盖。
- [ ] 至少受支持夹具的主/子请求→任务→会话→分支整条数据链可核对，不能全部 unknown 就关闭。
- [ ] 真实受控 Pi/子代理回执、重连/重启/取消负例与 Ego Lite 明细旅程分别留证；本地受控模型不代真实外部 Provider。
- [ ] 完成本票必需的 C/P/B 证据；按公开行为测试，保存源码/工作树、输入/运行身份、命令/退出码及失败，分别给出 Standards 与 Spec 结果。所有必需条件满足才关闭本票；原 Task 全部映射子项完成才迁移其状态。
