## What to build

用户用 @文件或编辑器代码选区生成材料卡片，检查来源和范围后发送；文件变化时由用户确认新版本或使用已冻结版本。

## Acceptance criteria

- [ ] 从实际项目文件选择及编辑器选区到卡片、预览、移除、发送与历史形成完整路径，保留文件、行范围、版本和摘要。
- [ ] 复用规范化、项目 realpath、符号链接与敏感路径检查，在读取及发送准入再次核验；拒绝越界、链接替换、错误项目和已失效身份。
- [ ] 文件被修改、删除或版本冲突时明确展示变化；未经用户处理不得悄悄读取新内容，已冻结输入的内容和范围不可漂移。
- [ ] 文本解码和截断有明确状态；材料资源上限与模型上下文预算分别检查，未知容量如实说明，超限要求缩小范围，不静默截断。
- [ ] 选择多个引用、切换项目、刷新和排队保留各自草稿与材料关联；失败不清空输入或隐式换账号。
- [ ] 真实 Pi 的最终输入与已确认文件/选区逐字对应，公开负例证明拒绝无读取泄漏或执行副作用，Ego Lite 完成选择到历史核对旅程。
- [ ] 完成本票必需的 C/P/B 证据；按公开行为测试，保存源码/工作树、输入/运行身份、命令/退出码及失败，分别给出 Standards 与 Spec 结果。所有必需条件满足才关闭本票；原 Task 全部映射子项完成才迁移其状态。
