## What to build

预览崩溃、端口冲突或 Host 重启后，用户能看到真实状态并通过受控入口恢复；未知残留不会被错误接管或清理。

## Acceptance criteria

- [ ] 在已安全可用的预览路径上交付崩溃→状态呈现→显式恢复、端口冲突处理、刷新重连和 Host 重启后的对账。
- [ ] leader 退出但后代存活时保留占用并拒绝重启，核对实际进程组/身份后才能释放或重用路径与端口，不能误杀无关进程。
- [ ] 恢复后保持同步与资源边界，Agent 再修改仍能看到正确更新；失败过程不向源写回、不损坏用户文件。
- [ ] 恢复/重新启动后重跑适用凭据泄漏和 HTTP/WS 重放负例，localhost 与 127.0.0.1 均保持隔离；旧配对状态不能被预览继承。
- [ ] 实际进程故障注入、锁竞争、残留清理和页面恢复分别留证，说明软件注入与物理故障范围。
- [ ] [U5-N05 / #54](https://github.com/Ricardo121380/only-my-pi/issues/54) 和本票全部满足 G5-04 后才关闭原 U5-04，PoC 及同进程 lease 负例不能代生产第二执行方的证据。
- [ ] 完成本票必需的 C/P/B 证据；按公开行为测试，保存源码/工作树、输入/运行身份、命令/退出码及失败，分别给出 Standards 与 Spec 结果。所有必需条件满足才关闭本票；原 Task 全部映射子项完成才迁移其状态。
