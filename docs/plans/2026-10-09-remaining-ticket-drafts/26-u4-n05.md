## What to build

用户在成功、失败、取消、长输出和分支会话中，仍能把结果、真实改动、验证状态和用量来源核对起来。

## Acceptance criteria

- [ ] 用同一真实 Host/Pi 候选贯通执行→应用/验证回执→请求用量→会话/子 Agent 聚合→实际页面。
- [ ] 覆盖失败、取消、长输出、重复事件、重启、分支及旧历史，结果事实不丢失、消费不重复、未知状态不虚构。
- [ ] 受支持夹具中所有选定用量来源均有正例，价格/缓存/上下文/有效生成时长与原回执可逐项对账。
- [ ] Ego Lite 从会话结果进入 diff/命令/验证与用量详情，来源、覆盖率和账号/模型一致。
- [ ] G4-01–G4-04 全部必需层及相关历史/输入/所有权回归通过，Standards/Spec 与原始证据齐备后才关闭 U4 阶段。
- [ ] 完成本票必需的 C/P/B 证据；按公开行为测试，保存源码/工作树、输入/运行身份、命令/退出码及失败，分别给出 Standards 与 Spec 结果。所有必需条件满足才关闭本票；原 Task 全部映射子项完成才迁移其状态。
