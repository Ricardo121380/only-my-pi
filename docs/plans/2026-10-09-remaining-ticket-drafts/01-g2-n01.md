## What to build

维护者能从一组身份明确、实际取得的来源和构建输入，核对当前 PDF 字体、CMap、worker、WASM、辅助模块与 QuickJS 资源的生成来路、完整材料和适用条件，形成可交给新资源构建的独立 PDF 材料候选。保留已有字节对应、历史未知和失败；需要新生成时以新身份接受验收。

## Acceptance criteria

- [ ] 以当前资源清单完整覆盖 PDF 资产和所需附带文本；保留已有 354 资产、10 份附带文本及固定源 blob 字节对应的证明范围，逐项说明新增、替换或集合变化，不能把来源字节相等升级为完整构建证明。
- [ ] 固定实际采用的原始字体/CMap 来源、各 WASM 与 QuickJS 的源码、构建脚本、精确工具链/环境及解析后的输入；worker 与两个辅助模块包含在对应关系中。既有候选输入、源码 revision 声明和历史工具版本字符串不替代实际取得的材料。
- [ ] 图标、字体、CMap、WASM 和其他混合资产分别绑定必要声明、版权/许可原文、适用范围和当前复制/生成条件；未解决的当前必需条件继续阻断，不用主包许可覆盖全部资产。
- [ ] 对需要新生成的对象，冻结来源、工具、配置和环境，在两个独立目录实际生成并核对完整输出集合及字节；保留日志、失败、新旧差异及本阶段可观察的内容/结构/接口兼容证明。无法复现或兼容性未核清的对象保持 PARTIAL。
- [ ] 优先保持现有组件版本和功能范围，历史材料不可取得时采用已约定的可核验新候选；更换组件版本、降低功能或接口变化须先单列影响并取得相应决定。旧候选、旧声明与未核项独立保留。
- [ ] 独立材料输出具有文件清单、摘要、执行位、来源回执和义务账本；通过最高可行公开材料入口完成 Node 22.19.0/24.19.0 校验、实际禁网和同策略网络拒绝，以及受影响的缺输入/漂移/别名/错误用途负例。原材料与失败证据不被改写。
- [ ] 当前 PDF 材料及操作条件全部满足才关闭；实际资源构建和运行兼容证明交接给 [G2-N02 / #25](https://github.com/Ricardo121380/only-my-pi/issues/25)/[G2-N03 / #26](https://github.com/Ricardo121380/only-my-pi/issues/26)，最终包及分发履行交接给 [G2-N04 / #27](https://github.com/Ricardo121380/only-my-pi/issues/27)，隔离 Full 交接给 [G2-N05 / #28](https://github.com/Ricardo121380/only-my-pi/issues/28)。每项后续义务携带对象身份、原文、适用前提和所需证据。
- [ ] 出口报告保留 Standards 与 Spec 两轴结果、源码/工作树及输入输出身份、命令/退出码和限制，只关闭 G2-00-03 的材料范围；F01、F03–F06、完整 G2-00 与 U2 不因此通过。
