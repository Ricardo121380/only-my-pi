# U2-N02：完成批量材料准备、配额与中断恢复

状态：OPEN；分流标签：ready-for-agent。执行前核对全部前置和操作条件。

## Parent

[总规格 #19](https://github.com/Ricardo121380/only-my-pi/issues/19)，原 Task U2-01，需求 US-017,US-018,US-028,US-029,US-032,US-033，并遵守 US-001–US-004。出口 G2-01、G2-04；必需证据 C/P/B。C 为合同/本地服务，P 为固定 Pi 与本地受控模型，B 为 Ego Lite 实际页面，I 为实际隔离或日常安装，L 为实际外部 Provider；各层分别留证。

## What to build

用户一次准备多个文本材料，看到每项和整组状态；只有符合配额且准备完整的集合可以提交，中断后能明确恢复或移除。

## Acceptance criteria

- [ ] 页面支持多文件选择并展示项目、来源、大小及逐项准备状态，独立上传结果组成为明确的发送集合；未完成或失败成员不能被静默漏发。
- [ ] 实际公开入口覆盖单文件 20 MiB、总量 50 MiB、最多 10 个与每文件文本 2 MiB 的边界和 +1；批量与并发不以多次小请求绕过总配额。
- [ ] 取消上传、网络中断、重复提交、刷新、多窗 revision 冲突和并发完成都保持稳定材料身份；重试准备不会重复发送模型任务。
- [ ] 只有完整且当前有效的冻结集合进入输入账本；发布失败及结果未知时明确阻断，草稿、已发送材料和旧历史保留。
- [ ] 临时对象有确定归属，取消或失败仅回收本次未被引用的自有对象；不得自动删除历史或其他会话材料来腾出空间。
- [ ] 通过实际页面操作、公开接口边界及真实 Pi 请求比较整组文件的顺序/身份/内容，记录批量恢复和残留核验结果。
- [ ] 批量组合按实际历史加全部冻结材料执行独立的上下文检查；覆盖每文件合规但组合超模型上下文、部分模型容量未知的公开入口与页面用例，要求用户明确处理范围，不静默漏掉成员或截断后发送。
- [ ] 完成本票必需的 C/P/B 证据；按公开行为测试，保存源码/工作树、输入/运行身份、命令/退出码及失败，分别给出 Standards 与 Spec 结果。所有必需条件满足才关闭本票；原 Task 全部映射子项完成才迁移其状态。
