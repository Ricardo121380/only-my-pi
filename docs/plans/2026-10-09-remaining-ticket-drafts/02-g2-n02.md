# G2-N02：从固定材料生成可运行的 native 构建候选

状态：OPEN；分流标签：ready-for-agent。执行前核对全部前置和操作条件。

## Parent

[总规格 #19](https://github.com/Ricardo121380/only-my-pi/issues/19)，原 Task G2-00-04 的构建切片，需求 US-013，并遵守 US-001–US-004、US-005/010。遵守 ADR-0017 的新旧身份与候选隔离约定；G2-00-04 须本工单和 [G2-N03 / #26](https://github.com/Ricardo121380/only-my-pi/issues/26) 都满足出口才完成。

## What to build

维护者能以已核验的新 native kit 和固定构建环境，执行实际配置、编译及链接，得到具有独立身份且可实际加载使用的 macOS arm64 native 产物。构建输入、最终锁、补丁和生成结果可以互相核对，不依赖旧 dylib、开发机隐含依赖或未绑定的工具。

## Acceptance criteria

- [ ] 开始前核对已验收 native kit、PDF 材料出口及所有当前构建前提；固定完整源树/子模块、补丁、兼容 overlay、347 完整 vendor 包、locale path override、工具链和 SDK 身份，记录真实平台与环境，漂移即停止。
- [ ] 给出单一明确的公开构建入口及有界执行配方，在新的隔离输出中使用完整私有依赖正式重新配置，执行实际 native 构建与链接；不能将五组 configure 冒烟、独立测试 crate 或复制旧二进制记为本候选构建。
- [ ] 构建按锁定、离线的输入约束执行，核对 lock 前后不变和实际补丁集合；缺输入、未审核 overlay、隐式联网补依赖、输入输出别名或工具漂移均拒绝并保存失败证据。
- [ ] 得到完整的候选二进制及依赖布局、清单/摘要/执行位、实际构建日志和源码到产物对应；动态链接只解析到明确允许的候选私有依赖或系统依赖，不能隐式借用旧 kit/旧 dylib 或开发 checkout 的资源。
- [ ] 通过候选实际加载和最小代表性功能探针证明产物可运行，并记录加载路径、输出和退出码；编译成功本身不等于功能通过。完整图片/Pi/RSS/PDF 资源矩阵由 [G2-N03 / #26](https://github.com/Ricardo121380/only-my-pi/issues/26) 验收。
- [ ] 核验此次实际构建所需的声明与条件，保留完整义务账本并交接最终包/分发和 Full 的后续项；组件升级、支持范围或接口变化先单列影响，不借构建排障更改已确认能力。
- [ ] 保存独立 binary/resource 候选身份、Standards 与 Spec 结果及构建/最小运行证据，保留原 kit、全部 supplement、旧合同和失败。kitId、二进制身份和 stackId 分列；本工单不完成默认发行、Full 或 U2。
