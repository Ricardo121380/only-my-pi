# U2-N04：粘贴或拖入图片并通过真实 Pi 发送

状态：OPEN；分流标签：ready-for-agent。执行前核对全部前置和操作条件。

## Parent

[总规格 #19](https://github.com/Ricardo121380/only-my-pi/issues/19)，原 Task U2-03，需求 US-021,US-022,US-028,US-029,US-030,US-033，并遵守 US-001–US-004。出口 G2-02、G2-04；必需证据 C/P/B。C 为合同/本地服务，P 为固定 Pi 与本地受控模型，B 为 Ego Lite 实际页面，I 为实际隔离或日常安装，L 为实际外部 Provider；各层分别留证。

## What to build

用户粘贴或拖入 PNG、JPEG、WebP，看到图片、必要转换与限制说明，发送后模型实际收到与卡片一致的图片内容。

## Acceptance criteria

- [ ] 三种支持格式都贯通选择/粘贴/拖入、准备、预览/移除、冻结、真实图片块投递和历史回看，不以 base64 文字替代 Pi 图片输入。
- [ ] 扩展名、内容类型和实际解码一致核验；40 MP、单文件/批次配额、解码时间和资源限制实际生效，覆盖透明图、大图、损坏图及伪装格式。
- [ ] 转换或缩放记录原始与发送版本、策略、尺寸及摘要，卡片能说明发送的实际版本；不无提示丢失必要内容。
- [ ] 按绑定模型的真实能力检查图片支持；不支持则阻止发送并保留草稿，不丢图继续执行、不静默换模型。
- [ ] prompt、即时补充及队列的图片载荷与 inputId/回执关联保持一致；消费待核对、重连、取消、刷新不能重新发送或换图。
- [ ] 真实 Pi/loopback 模型请求核对图片块、内容及顺序，Ego Lite 验证完整旅程；支持 Node 两侧的受影响解析与输入合同回归通过。
- [ ] 图片与正文/历史组合的模型上下文或容量估算按可获得来源独立核对，超限要求用户处理，图片 token 或容量未知时明确说明，不以文件大小/像素配额内推定一定可容纳。
- [ ] 完成本票必需的 C/P/B 证据；按公开行为测试，保存源码/工作树、输入/运行身份、命令/退出码及失败，分别给出 Standards 与 Spec 结果。所有必需条件满足才关闭本票；原 Task 全部映射子项完成才迁移其状态。
