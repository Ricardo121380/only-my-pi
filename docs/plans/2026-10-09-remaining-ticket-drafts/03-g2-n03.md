# G2-N03：形成新图片与文档资源候选并通过运行矩阵

状态：OPEN；分流标签：ready-for-agent。执行前核对全部前置和操作条件。

## Parent

[总规格 #19](https://github.com/Ricardo121380/only-my-pi/issues/19)，原 Task G2-00-04 的资源整合与验收切片，需求 US-013，并遵守 US-001–US-004、US-012。出口为新 F01 身份及 G2-00-04 的适用运行矩阵；与 [G2-N02 / #25](https://github.com/Ricardo121380/only-my-pi/issues/25) 一起完成该原 Task。

## What to build

维护者能把已实际构建的新 native 产物、已闭合的 PDF 构建材料、当前有界解析 worker 和辅助模块组成完整图片/文档资源候选，在隔离副本中真实加载并核对功能、预算和 Pi 互操作，获得可交给默认发行链的资源身份。

## Acceptance criteria

- [ ] PDF 资源需要重建的部分使用 [G2-N01 / #24](https://github.com/Ricardo121380/only-my-pi/issues/24) 绑定的来源、工具和配方实际构建；与 [G2-N02 / #25](https://github.com/Ricardo121380/only-my-pi/issues/25) 的 native 产物一同形成两棵完整、固定的文档/图片资源树，包含当前 PDF 预算 worker、两个辅助模块及必需 font/CMap/WASM，所有输出与材料和构建证据逐项对应。
- [ ] 新资源合同绑定精确包/lock、平台、支持 Node 版本、生成策略、完整文件集合/大小/摘要/执行位、链接准入及来源声明；保留旧 F01 和旧合同，不仅替换摘要或把 U0_REHEARSAL 的未完成声明改成 PASS。
- [ ] 验收入口显式接收当前候选及冻结语料身份；先保持原有有效行为，再去除对历史绝对语料位置的隐含依赖。不得通过读取旧 capacity 目录或开发根依赖，使缺材料的新候选获得通过。
- [ ] 在 Node 22.19.0/24.19.0 使用当前候选实际运行完整适用图片、文档、容量/RSS及固定 Pi 矩阵；覆盖 PNG/JPEG/WebP、四种现代文档、真实位置/partial、损坏/加密/不支持、像素/页数/展开/输出/时长边界和 PDF 累计展开的缓存/恢复/重置，保留冻结上限。
- [ ] 通过隔离资源包的注入、重打包、解包及实际加载往返验证完整集合，并记录真实加载路径；包括实际禁网、同策略网络拒绝、缺资源、同名同版本摘要冲突、错误平台/Node/用途、未知合同和未审核 overlay 等适用负例。
- [ ] 旧新候选的材料、生成结果及运行行为差异逐项解释；功能/接口兼容和运行矩阵全部满足，才能将本切片及新 F01 记为通过。[G2-N02 / #25](https://github.com/Ricardo121380/only-my-pi/issues/25) 的最小 smoke、历史 U0 或旧 dylib 结果不能补新矩阵缺口。
- [ ] 输出独立资源候选、完整合同、义务交接及 Standards/Spec 结果；分列 C 与实际 Pi 的 P，保留 F02 的适用证据与尚待最终分发/Full 的条件。此处验证是隔离候选，不是默认发行或安装态 Full 通过。
