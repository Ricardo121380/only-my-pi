# U2-N01：上传文本材料并冻结后发送给真实 Pi

状态：OPEN；分流标签：ready-for-agent。执行前核对全部前置和操作条件。

## Parent

[总规格 #19](https://github.com/Ricardo121380/only-my-pi/issues/19)，原 Task U2-01，需求 US-017,US-018,US-028,US-029,US-030,US-033，并遵守 US-001–US-004。出口 G2-01、G2-04；必需证据 C/P/B。C 为合同/本地服务，P 为固定 Pi 与本地受控模型，B 为 Ego Lite 实际页面，I 为实际隔离或日常安装，L 为实际外部 Provider；各层分别留证。

## What to build

用户从页面显式上传一个文本文件，看到准备结果和来源，随正文发送后能在真实 Pi 请求与历史中核对同一份冻结内容；页面刷新仍保留未发送材料。

## Acceptance criteria

- [ ] 上传独立于 prompt，以稳定材料身份关联项目、会话和消息；Host 原子完成材料发布后才能引用，浏览器不得指定任意主机源路径。
- [ ] 最小闭环包含材料卡片、加载/完成/失败/移除、保存与刷新恢复；未接入类型明确不可用，不能先放行文件名占位。
- [ ] 从首个实现开始绑定实际发送字节、摘要、来源与材料版本，inputId/contentDigest 和消费回执保持一致；原件变化不改变已接受内容。
- [ ] 单文件 20 MiB、每文件文本 2 MiB、提交 50 MiB/10 个材料的总界限在公开入口生效；首片可只开放单文件交互，但不得绕过这些界限或放大全部路由的请求体。
- [ ] 覆盖伪装格式、跨项目材料 ID、未完成上传、同 ID 内容冲突、磁盘不足、持久化结果未知与断连；失败保留旧草稿和历史，未知投递先读回执，不自动重发。
- [ ] 页面→公开 Host→固定 Pi 的本地受控模型收到精确文本，并能对应卡片、持久记录及执行历史；Host 认证、Origin、协议、授权和纯文本原流程回归通过。
- [ ] 模型上下文与材料资源配额独立检查：覆盖文件/文本配额内但加上实际历史已超过模型上下文的用例，要求用户明确缩小或移除材料；容量无法可靠取得时显示未知并说明范围，不静默截断或冒充可完整容纳。公开 Host 与页面拒绝/待处理状态均可核对。
- [ ] 完成本票必需的 C/P/B 证据；按公开行为测试，保存源码/工作树、输入/运行身份、命令/退出码及失败，分别给出 Standards 与 Spec 结果。所有必需条件满足才关闭本票；原 Task 全部映射子项完成才迁移其状态。
