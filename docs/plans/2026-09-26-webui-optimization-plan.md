## 3. 设计合同与完整用户旅程

设计工作使用用户指定的 `ui-ux-pro-max`、`frontend-design`、`frontend-ui-craft`；实施时读取对应技能，保留现有技术栈。Open Design K3 沿用既有可选辅助约定，使用前核实入口和模型，不可用时当前 Codex 继续。不会为计划文档调用收费设计服务。

U0-02 产出可检查的布局、组件状态与操作样稿，再用于实现。没有重新逐像素复刻旧 HTML 的要求；旧原型的视觉资产可复用，模拟行为不能直接用作生产实现。

主使用链路：

1. 打开项目与会话：默认进入已停止会话的续接输入；历史账号/模型仍有效则明确显示并沿用，缺失或不可用时要求选择，不静默换账号。新建操作单独呈现。
2. 提交需求：文字、@文件、代码片段、粘贴图片、拖入文档统一成为可检查的材料卡片；展示解析、范围、错误及可获得的用量提示。
3. 执行中：突出实际步骤、待处理审批、排队或锁占用原因；详细工具记录展开查看，不编造百分比。即时补充和排队语义不同，停止是独立动作。
4. 查看结果：摘要列出修改文件、验证结果和未完成事项；点击进入统一差异视图，能回到对应消息、工具或验证回执。
5. 继续工作：原会话接着聊，或从指定消息分支；项目文件不回滚。需要人工编辑或终端时仍遵守写入协调。
6. 测试与预览：显式运行配置过的项目命令，查看真实结果；预览存活时 Agent 能继续修改，服务异常有恢复入口。
7. 整理与离开：分区/搜索/归档找回历史；刷新保留草稿和队列；Host 重启或任务异常后暂停待处理输入，不自动重放。

所有新增关键控件覆盖：未选择项目、空内容、加载、处理中、待审批、等待所有权、成功、部分成功、失败、断连、只读/禁用及缺少能力。技术错误码进入详情，面向用户的主文案描述原因和下一操作。

## 4. 实现合同

以下是依据已确认需求制定的工程方案。模块名和资源上限是计划默认值，不冒充用户逐项选择或当前已实现事实；U0 用证据调整工程细节时记录差异，不能降低已选功能或绕过原有边界。

### 4.1 历史、任务与消息归属

- Pi 历史仍是已执行对话的权威；Host 管理未发送草稿、待投递消息、队列、GUI 元数据、附件及使用回执。不用当前裁剪过的任务摘要保存完整草稿或队列。
- GUI 元数据放 Host 私有状态根，不写用户项目或混入凭据；复用原子写入和版本校验，默认不增加数据库。全文索引可重建，与原历史分离。
- 队列项包含稳定 ID、会话/项目、账号/模型/强度、执行模式、材料快照引用、配置版本及顺序；发出时再次验证。切换账号或配置不悄悄改写已排队内容。
- 队列状态至少区分草稿、已排队、暂停、投递中、已确认、结束、投递待核对。幂等 ID 与内容摘要相同才可确认同次请求；相同 ID 不同内容拒绝。
- “已收到”只证明 Host 接收；运行时队列确认不等于模型已处理。只有能关联权威消费事件或历史消息时显示已生效；缺失确认保持待核对，不能以计时器推断成功。
- 工具运行期间的即时补充不强停当前工具，不扩大授权；U0 核实 Pi steer 对后续待执行工具的行为，准确告知能生效的边界。
- 排队项按 FIFO，可在尚未投递时编辑/删除。前一任务成功且身份/材料/配置仍有效时允许推进；待审批、失败、取消、状态未知、Host 重启时暂停。后续任务重新做必要授权，禁止复制上一任务许可。
- 取消当前任务保留未投递队列但暂停；已经投递的补充不能再显示成可撤回草稿。断连重连先查询，不重放执行命令。竞态中当前任务已结束时，不把即时补充静默转成新付费任务。
- 本机多窗口共享 Host 状态，通过版本冲突提示保护草稿/队列；新建草稿按项目隔离，已有会话按稳定会话 ID 隔离。

改动落点：`packages/host/contracts.*`、`tasks.mjs`、`rpc-worker.mjs`、`server.mjs`、`control-state.mjs`、`webui/src/App.tsx`、`Composer.tsx`、`TaskControl.tsx`、`useHost.ts`。拟新增消息队列/草稿存储模块；名称在 U0 冻结，不在未存在文件上建立虚假链接。

### 4.2 材料、文档与快照

- 项目引用沿用路径、符号链接和项目范围校验；外部附件只能来自用户明确上传，不借引用接口读取任意主机路径。选中代码记录文件与行范围。
- 文件准备与任务提交分离：上传/解析返回材料 ID，任务按 ID 引用冻结后的内容。不能把 base64 文档或全文堆进现有 32,768 字符 prompt 字段，也不能为附件扩大所有 HTTP 路由的上限。
- 上传扩展名、内容类型和实际内容共同检查；解析进程独立、有时间/内存/解压/输出边界，不运行宏、脚本、公式计算或远程资源。XLSX 区分公式文本与已有缓存值，避免把未计算值当实时结果。
- 来源保留 PDF 页、DOCX 标题/段落/表格、XLSX 工作表/单元格、PPTX 幻灯片位置。Office 无可靠页码时不伪造页码；扫描页、空内容、部分提取均明示。
- 图片通过 Pi 的真实图片输入链路；执行前检查当前模型能力。模型不支持时要求用户更换模型或移除图片，不丢图后照常发送，不自动换模型。
- 已验证并冻结的工程上限：单文件20MiB、单次原始材料50MiB/最多10个；图片40MP；PDF200页、PPTX200张、XLSX20万非空单元格；每文件文字2MiB；实际展开200MiB/ZIP一万个条目；文档30秒/worker512MiB采样阈值。依据U0固定双Node的选定样例，非所有合法输入都成功或OS硬内存保证；产品上传/混合材料/并发还须U2验证。
- 文件通过解析不代表能全部装入模型上下文。依据可获得的模型容量、历史与材料估算提示；不能确定时标未知，超限时让用户缩小页/表/片段范围，不静默截断。估算口径与最终 Provider 用量分开。
- 已发送快照包含实际文本/图片版本、来源、摘要、解析器版本及范围；历史不依赖原文件当前内容。原始上传为重新解析需要可保留，清理 UI 分列原始文件与已发送内容，避免误解空间与可恢复性。
- 删除草稿附件不删原项目文件；归档不删材料；清理已发送内容需明确影响。按消息/分支引用检查共享内容，不能清一个会话就破坏另一个；清理后保留不可用标记，不虚构引用已失效内容。磁盘不足时拒绝新增并保留既有数据，不自动删除用户历史。

### 4.3 项目整理、全文检索与分支

- 分区仅为组织方式：创建、重命名、排序和项目归类不迁移磁盘目录。原“本机”作为未分组项目入口；会话重命名/置顶/归档是 GUI 元数据，不破坏 Pi JSONL。
- 全文搜索覆盖已登记项目的可读取用户/助手消息，结果携带项目、会话、时间、消息定位和匹配片段；名称搜索继续可用。工具日志和二进制附件不自动扩大为全文检索范围。
- 不索引凭据、隐藏模型内部思维链或整个磁盘；归档通过显式过滤可查。索引重建期间提示范围与进度，历史新增/损坏/删除有独立状态，不显示旧索引为当前完整结果。
- 分支从已停止会话中的有效消息位置生成新的会话身份；读取源和创建目标都经准入。使用公开 SessionManager/RPC 合同；附件引用关联到分支位置为止，不复制运行中队列、授权或活动进程。
- 原会话保留，共用当前代码；分支前提示“不还原文件”。继承上下文的历史消耗单列，不能计成新分支已发生消费。

### 4.4 审查与统计

- 主摘要固定区分任务是否结束、修改是否应用、工作区验证是否通过；不把模型自述或绿色终态代替验证回执。
- 当前项目总 diff 可能含用户原改动；会话/任务修改必须有基线或回执才能归因。旧历史无法归因时标明“当前工作区差异”，不得声称全部由该任务产生。
- 执行事件有稳定身份并去重；请求、工具、主/子 Agent 的范围均可解释，重连/分支不重计。会话汇总需要覆盖记录，旧数据不能追补的字段标部分或未知。
- 缓存 token 依据 Provider/Pi 字段语义归一化，不统一假设 input 是否已含缓存；保存来源和计算口径。费用采用当次可用单价快照和币种，不用当前价格重算旧历史。
- 上下文使用实际请求/运行时快照，不能用累计消费代替。生成速度仅在有输出 token 与有效生成时间时计算，排除排队和工具等待；首 token 延迟单列。若内核不提供所需时刻，做明确事件采集或保留未知，不能以总任务时长冒充。
- 主/子 Agent 分列并说明汇总覆盖；局部未知不变成 0。至少在选定受支持测试路径上证明来源和汇总，不能以所有指标均未知满足“完整用量”。

### 4.5 已有技能/扩展配置

- OMP 产品配置管理两端共用的默认值与项目覆盖，可看到来源、可配置项、请求状态和实际加载状态；下次执行生效，不热改当前任务。项目覆盖和重置在两端具有相同含义，配置写入冲突明确处理。
- 只管理已存在、可识别、归属可验证的资源。对有公开配置 Schema/声明的资源提供相应编辑入口；没有声明时明确不支持通用字段编辑，不提供执行任意代码的“配置”框。新增 Provider 凭据走独立账号认证入口，CLI 与图形端均须可操作。
- 强制 OMP 权限/所有权/预算扩展不提供关闭；必需集合与可选集合分开。启停失败不得绕过受控资源过滤器；不能支持的扩展明确解释兼容原因，而非展示假的已启用。
- 队列绑定配置版本，版本变化时暂停受影响排队项并明确处理；原 Pi/CLI 资源、默认凭据与外部包保持原归属，仅显式导入。共享产品配置不合并账号身份，也不授予执行权限。

### 4.6 项目命令与并行预览

- 项目设置提供具名测试/构建/预览配置，明确工作目录、命令、启动/结束状态、退出码和输出。可发现脚本作为建议，未经用户启用不执行；不将配置持久化解释为已经运行命令。
- 测试/构建按可能写入项目处理，仍与 Agent/人工编辑轮流取得所有权。已有后台服务不能借“只是预览”名称被当成只读。
- **预览并行是独立技术门禁。** 优先验证受管预览副本或受约束只读源读取＋独立派生输出目录；不靠命令名称、环境变量、前后摘要或允许写缓存的声明证明任意脚本不会写原项目。若采用同步副本，须证明Agent改动可及时呈现、不会向源目录写回，且不是用户排除的Git分支工作流。
- U0 在本机协作威胁模型下确定可支持的预览配方、源/缓存/输出边界、依赖访问和进程清理机制，覆盖误写源目录的负例。不得把这称为任意恶意代码 OS 沙箱；不能建立满足原项目单写的方案则记录 BLOCKED，不将普通 PTY 放锁冒充并行成功。
- 同时运行验收包含受控 Agent 修改→预览更新、预览重启、端口冲突、刷新后重连、明确停止及 Host 退出。未知子进程状态不自动重用路径/端口或释放相关占用。
- 预览面板与 Host 控制页面分离来源与权限，不注入 Host token，不开放任意URL代理/跨站访问；显示确切本机来源。嵌入受限时可显式在独立浏览器标签打开同一受管预览，不能绕过来源校验。
- U0-06/G0-05 与 U5-04/G5-04 必须覆盖凭据泄漏和重放：配对后访问预览、预览收到的请求头/环境、预览服务端伪造 Host/Origin/协议头访问 Host API 和 WebSocket。Cookie 不按端口隔离，单独不同端口不构成凭据隔离；`localhost` 与 `127.0.0.1` 区分测试。不得在预览来源获得 Host 认证资格；修复方案须以实际请求负例证明，不能只改来源标签。[RFC 6265 §8.5](https://www.rfc-editor.org/rfc/rfc6265#section-8.5)
- 不为了预览擅自安装容器平台、改系统权限、开放公网或下载用户项目依赖；如最终方案确需新增环境，先给具体证明和影响。

## 6. 验证与运行约束

现有脚本入口已核对根 `package.json`：`npm test`、`npm run typecheck`、`npm run lint`、`npm run pack:check`、`npm run test:host`、`npm run test:web`、`npm run build:web`。无需在不存在的 `webui/package.json` 中运行独立包脚本。S0-01冻结适用完整自动化清单及运行环境；S0-08、后续批次集成与U6候选晋级按影响范围执行该完整清单及新增检查，受影响旧测试必跑。纯文档和小任务仍优先定向验证；同一未变化候选的有效证据可复用，不能用“不重复全量”排除新发现失败或必需集成门禁。既有发布门禁不在本轮未经评估删除，也不把收费验收或公开发布混入普通全量测试。

浏览器使用 Ego Lite 与 `ego-browser` 技能；不可用时页面验收为 NOT_RUN，不静默替换工具。组件/模拟服务证明机制，固定Pi真实子进程证明协议，真实Provider与日常安装分别证明互操作和交付。

性能继承既有目标：本地输入 P95 <100ms，取消本地确认 P95 <500ms，10,000事件、5MiB工具输出和长diff样本；新增解析/检索在后台处理，不能阻塞输入。新增全文样本建议100会话/10万条消息，热索引查询P95<500ms；预览样本连续20次变更，页面反映P95<2秒。上述新增值是验收目标，U0确认固定样本与硬件，非当前已测结果。

真实模型验收的建议新增包为 **3个小型场景＋至多1次失败重试，总额最多4次场景尝试**：材料与续接；即时补充/队列/取消；受控修改/子代理用量与并行预览。每次允许的主轮次、子代理轮次、token与时长在执行前脚本中绑定，不能把一次场景当无限会话。所需模型图片能力、路由及预算另行明确；不静默切换CPAR/Grok或其他Provider。Q23确认的是计划成稿，不是新增收费调用授权，当前预算状态为未授权、已用0。

本轮不推送、不公开发布、不改全局配置。最终日常安装按原支持的Full流程准备候选、备份与回滚证据，核对活动会话和具体授权覆盖后执行，不强停用户工作；先隔离安装，再日常晋升。历史和凭据不随代码回滚覆盖。
