## 2. 上游变化与本项目核验点

下列变更来自官方 [1.2.0](https://github.com/earendil-works/pi/releases/tag/v1.2.0) 和 [1.3.0](https://github.com/earendil-works/pi/releases/tag/v1.3.0) 发布记录。影响判断是根据当前接线作出的预检推断，尚未通过新版源码/API diff 或运行验证。

| 上游变化 | 必须核对的 OMP 行为 |
| --- | --- |
| 1.2：启动事件增加消息类型，启动期间计为 busy | inputId 关联、即时补充/FIFO、结束竞态、取消及任务状态不能因事件形态改变而误判 |
| 1.2：MCP 资源声明及工具结果/展示变化；OAuth 等待期间取消处理修复 | 发现与调用权限分别核验；刷新后再检查取消/授权/目标；资源读取和未知结果保持原边界 |
| 1.2：移除未发行的实验 server/client/plugin 栈 | 继续使用已选正式 RPC/SDK；核查无实验导入，不引入替代执行平面 |
| 1.3：恢复会话保留 active tools，跨模型处理历史 thinking 的方式改变 | 历史可读/可续接，工具集合仍经 OMP 准入；恢复不继承旧授权，不将隐藏推理呈现为回答 |
| 1.3：内部包精确绑定，codemode 存活 worker 限制与取消修复 | 候选依赖同版本；并发/取消/超时后真实进程退出，未知所有权不能提前释放 |
| 1.3：畸形工具 JSON 拒绝与 Provider 重试修复 | 合法工具继续工作，非法参数零执行；按接收计数验证请求/预算/错误/取消，不因内部重试增发 |

## 4. 直接 Pi 接入与封装核查

产品目标已明确为 CLI/TUI 与桌面两个正式客户端，图形端先交付 WebUI。当前 CLI 的 [launcher](../../packages/direct-agent/launcher.mjs) 用 `execve` 进入 Pi CLI/SDK 接入入口；图形端的 [账号入口](../../packages/host/account-rpc-entry.mjs) 已直接创建 Pi SDK 会话，再通过 RPC 服务现有 Host。Host/worker 是当前实现安排，不作为新版必须照搬的独立架构层。

按官方 1.3.0 的 [SDK](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/sdk.md) 与 [RPC](https://github.com/earendil-works/pi/blob/v1.3.0/packages/coding-agent/docs/rpc.md) 文档，PI130-01 应先完成以下对照，再决定具体修改：

- Node 进程可直接嵌入 SDK；先核查现有任务管理与 Pi 会话/事件/队列的职责，保留必要产品状态，定位重复实现。
- 若仍需 Pi 子进程，评估上游 `RpcClient` 对启动、请求关联与事件分发的覆盖；账号注入、审批 IPC 和输入确认等附加行为须另行对照，不能推定可直接替换整个 `RpcWorker`。
- SDK 会话不会自动装配 CLI 的 MCP、codemode、tool search 内置扩展；采用直接 SDK 时必须显式装配并核验相应能力，不把示例可启动视为产品等价。
- 进程数量按故障影响、取消/退出、多任务和账号环境需求决定。删除封装须有行为等价证据；本次预检没有执行进程合并、替换或功能删减。

## 5. 验证与交付要求

复用根 [package.json](../../package.json) 的实际命令；支持矩阵沿已确认 Node 22.19.0 / 24.19.0。此次文档检查使用本机 Node 26.8.2，不算该支持矩阵验收。

- 第一层：`npm run typecheck`，受影响的 CLI/Pi/Host/MCP/codemode/分类/生图/输入/历史测试，涉及前端时 `npm run test:web` 与 `npm run build:web`；具体文件列表在接口 diff 后冻结。
- 第二层：分别从公开 CLI 与图形端接入入口 → 真实 Pi 1.3.0 → loopback 服务；观察实际请求数、身份、输入消费、文件结果和持久回读；不能只由 SDK 帮助函数测试通过。
- 第三层：同一私有候选分别执行实际 CLI/PTY 旅程与 `omp web` 的 Ego Lite 正负旅程；CLI 独立验证启动、对话/审批、工具执行、取消/退出和历史续接。
- 收口：`npm run lint`、`npm run pack:check`、适用完整回归及候选所需检查，Standards 与 Spec 分列。保留初次失败，修复后仅重验受影响部分及必要整合。
- 安装与外部服务：完整 parser、Full、真实 Provider、日常晋升沿原独立门禁；本轮不以版本预检代替任何一项，不运行真实账号/MCP 或收费模型。
