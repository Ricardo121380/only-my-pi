# Pi Agent · Glacier — Web-first Agent UI

**日期：2026-09-21**  
**交付状态：可交互 HTML 原型；未接入真实项目。**  
**路线：先 React WebUI，再复用同一套界面进入 Electron。**

本轮延续用户认可的 Tide 布局与圆润几何，不重新复刻 Codex。定位是 Agent 开发工具：任务、授权、文件结果、执行输出和运行成本需要互相衔接。这里的项目定位来自用户任务，不代表已经通过连接器识别了 only-my-pi 的现有代码架构。

## 1. 稳定的信息结构

唯一导航包含关系是 **分区 → 项目 → 会话**。分区用于组织项目；项目承载目录、环境属性、文件和会话；会话承载消息、草稿、运行与审阅记录。运行环境与分支是项目／会话属性，不增加“工作空间”层级。

项目主页、任务会话、右侧面板仍保留原来的关系。新增底部 Terminal 不挤占右侧的职责：右侧负责「预览／变更／活动」，底部负责执行输出与终端。桌面上二者可以同时打开，也可独立收起。主页不堆叠额外监控大屏。

## 2. 配色、几何与玻璃

本轮主色由青蓝转为冰川蓝，青色退到状态与微弱环境色，形成更偏工程工具的冷色系统。颜色不随当前模型品牌切换。

| 语义 | 浅色 | 深色 |
|---|---|---|
| 画布 | `#F4F6FB` | `#141923` |
| 内容实底 | `#FFFFFF` | `#1C2330` |
| 次级表面 | `#F1F4F9` | `#252E3D` |
| 主文字 | `#202A3B` | `#E9EEF7` |
| 次文字 | `#616E83` | `#B2BED0` |
| 品牌文字／选择 | `#3D64D8` | `#A8BFFF` |
| 主按钮 | `#456BE5` | `#456BE5` |
| 辅助信号青 | `#208B9C` | `#86CDDA` |

成功、警告、删除采用独立语义色，不把一切状态染蓝。深色使用单独表面与文字变量，不反相。

**加强的位置：**输入托盘、右上角面板控制组、侧栏表面与边缘。托盘使用两层细边、轻微内部高光、冷色透底和接触阴影；侧栏保持更柔和的磨砂。小控件在同一玻璃容器里使用薄填充，不再叠一层高强度模糊。对话、代码、终端正文和权限内容保持稳定底色。

Apple 将 Liquid Glass 定位于导航与控制层，并提醒避免玻璃叠玻璃和让内容层竞争层级。[1] 本方案采用这个层级原则，但使用的是 CSS 近似材质，不是 Apple 原生的自适应折射实现。

设置提供「轻简／均衡／通透」三档。减少透明度和增强对比度可覆盖玻璃效果；系统减少动态效果偏好优先。不支持背景模糊时回退实底。

输入框圆角 29px，主要卡片 24px，导航选择面约 17px；文字按钮用胶囊，常用图标用圆形。手机输入框 25px。间距与嵌套圆角协调，不靠把每个控件放大来制造圆润。

## 3. 独立底部 Terminal

右上控制组的两个按钮分别表示底栏与右侧栏，状态与工具提示独立。快捷键 `Ctrl + \`` 打开底栏；鼠标拖动顶部握柄改变高度，键盘聚焦分隔线后用上下键或 Home／End 调整。

Terminal 在桌面跨越对话和右侧面板下方，不覆盖左侧项目树。窄屏变成底部模态面板，背景不可交互；Escape 关闭并恢复焦点。右侧审阅与手机 Terminal 不同时叠成两个活动模态层。

**终端与任务的生命周期分离：**收起底栏不终止任务；清空显示不停止进程；停止是单独动作。Agent 输出是只读日志，手动终端另有标签和输入区。终端草稿按项目与标签隔离，可新增／关闭模拟标签。

模拟器支持 `help`、`pwd`、`git status`、`clear`；构建／测试转入单次确认。其他字符串明确标为未执行。本轮没有使用真实 PTY 或调用 shell。

这个入口借鉴 Codex 官方集成终端说明中的右上角开关、项目／会话上下文与命令验证工作流。[2] 标签、独立底栏及本方案的分区关系是自己的组合，不复刻对方所有导航。

## 4. 输入框下方的性能与费用

依据用户提供的 DeepSeek Harness 截图，保留轻量两行排布；指标点击后展开，不额外占据右侧。

**第一行：本次提交触发的运行**  
`模型请求次数 / 工具调用次数 · 生成速率 · 输入+输出 · 缓存命中率 · 本轮估算`

**第二行：会话累计**  
`模拟指标 · 本会话费用 · 输入总量（含缓存） · 输出 · 口径`

「本轮」可以包含多次模型请求，不等同于一条 HTTP 请求。计数来源需要在真实运行层去重；工具重试不能被 UI 事件重放重复累计。

### 原型样例的可核对口径

| 指标 | 本轮样例 | 定义 |
|---|---:|---|
| 输入总量 | 188,000 | 已包含缓存读取 |
| 缓存读取 | 167,320 | 输入的子集，不再额外加到总量 |
| 输出 | 8,200 | 单独的输出量 |
| 输入+输出 | 196,200 | 188,000 + 8,200 |
| 缓存命中率 | 89% | 167,320 / 188,000 |
| 有效生成时长 | 34.6 秒 | 演示值，非浏览器性能实测 |
| 生成速率 | 237 tok/s | 8,200 / 34.6，取整 |
| 当前上下文 | 84K / 200K | 示例容量，不是会话累计消费 |

虚构单价：未缓存输入 $0.80、缓存读取 $0.16、输出 $0.82，均为 USD／百万 tokens。结果 `(20,680×0.80 + 167,320×0.16 + 8,200×0.82) / 1,000,000 = $0.0500392`，UI 显示约 $0.0500。10 条样例记录的累计费用为 $0.502196，显示约 $0.5022。**这些不是供应商报价、真实账单或模型基准。**

用户截图里各数值的底层定义没有从 web-ui-all 源码核实。本方案借鉴它的位置与信息密度，不声称复用了 DeepSeek Harness 的计费公式。

### 数据边界

未知用 `—`，不是 0；没有运行时显示空状态；停止保留部分记录，不能伪装已完成。详情含「本轮／本会话／指标口径」、首 token 延迟、缺失状态预览与 JSON 导出。导出明确标记 fixture 与虚构价格。

正式接入时，每个请求保留 provider、model、时间、单价快照和来源。切模型不会重算历史单价；多币种分别汇总，不擅自换汇。缓存写入、不同 TTL、推理输出等依供应商规则归一化；已计入 output 的推理 token 不再重复计费。缺失计费项时显示覆盖不全。上下文来自当前请求而非消费累计；速率用输出量与有效生成时长，不混入工具、排队、重连等待。

## 5. 其余功能与动效

新增的上下文环可查看占用、引用和模拟压缩；推理强度独立选择，不支持的模型在生产版应隐藏此控件。会话支持「从这里分支」：复制消息快照，不复制单次授权、队列、运行、消费记录或真实 Git 分支。活动页集中当前项目的运行与待确认项，跨会话点击返回对应记录。

Claude Code 桌面版文档提供模型旁上下文入口与逐文件差异审阅的参考。[3] Pi-Desktop README 列出了会话分支、排队输入、@ 文件引用、差异和命令输出等长期任务工作流。[4] 本轮只确认了这些公开说明，没有完成 Pi-Desktop 前端源码逐组件审计。DeepSeek Harness 官方介绍为插件能力与执行记录组织提供依据；当前 UI 只显示公开执行输入／输出与摘要，不展示内部思维链。[5]

沿用用户研究报告的分层方法：基础变量与通用控件、局部产品微动效、Agent 工作流模式各司其职，而不是安装五套不同视觉系统。[8] 当前单文件没有安装这些组件库。

动效约定：按钮反馈 120ms、常规切换 190ms、面板布局 300ms；标签指示器与上下文环连续过渡，状态摘要轻微淡入。日志和 token 数字不逐字符弹跳；数字使用等宽数字样式；不用全屏粒子、鼠标追光或常驻大面积动态模糊。本轮没有完成 GPU、耗电或长期帧率基准，不能把轻量实现等同于已通过性能认证。

## 6. WebUI → React → Electron

**本轮文件是 HTML/CSS/JavaScript 原型，不是已经完成 React 化。** 后续以当前项目实际代码为准拆分，建议职责如下；名称是候选组件，不是仓库现有路径。

| 拟议组件 | 职责 |
|---|---|
| `ProjectTree` | 分区／项目／会话及草稿定位 |
| `SessionView`、`Composer` | 消息、队列、模式与输入 |
| `UsageStrip`、`UsageDetail` | 格式化指标，不自行猜测计费规则 |
| `Inspector` | 预览、变更和活动 |
| `TerminalDock` | 终端可见性、标签、布局，不拥有进程生命周期 |
| `ApprovalCard` | 呈现服务端待确认请求，提交明确决策 |
| `HostAdapter` | 隔离 Web 后端连接与 Electron preload 能力 |

先把浏览器前端和真实 Agent 事件连接稳定，再进入 Electron。Web 版通过授权后的后端接口获取文件、PTY 与运行事件；普通浏览器不直接访问本机 shell。Electron 版复用同一 React 界面，改变宿主适配与桌面能力，不复制两套 UI，也不以 SwiftUI 重写为前提。

Electron 的 `setVibrancy` 有 macOS 窗口材质能力，但不意味着每个 DOM 元素自动获得 Apple 原生 Liquid Glass。[6] macOS 专属原生增强作为后续可选验证项，不能阻塞 Web 或跨平台交付；当前设计包没有实现或验证它。

执行与权限归宿主／后端所有。采用隔离 renderer、受限 preload 和具名能力接口；验证 IPC 来源、参数、作用域与授权有效性，不把原始 ipcRenderer 或 shell API 暴露给页面。生产 Electron 资源加载应按官方安全建议评估受控自定义协议，而非照搬原型的文件打开方式。[7]

`integration-contracts.ts` 给出拟议类型：使用请求级用量快照、事件 ID 与序列号去重，取消先进入 stopping，再等待权威确认。重放事件不能重复执行或重复计费。TypeScript 检查通过只说明类型声明自洽，不替代运行时验证、安全检查或真实适配。

## 7. 验证、交付与限制

本轮最终 HTML 在 Chromium 144.0.7559.96 下完成 **114／114 项交互与布局断言**。测试包含两面板独立性、终端高度、隐藏后执行连续性、标签草稿隔离、单次授权、重放阻止、只读、分支隔离、用量计算与停止／排队记录、缺失展示、导出、明暗与辅助显示。尺寸从 360px 至 1920px，含 761px 窄桌面边界；发送按钮既在视口内，也在输入托盘内。

测试用 fresh page + set_content；环境禁止 file://。没有验证本机双击路径、持久存储、Safari、Firefox、VoiceOver、Electron 打包、原生 Liquid Glass、真实 Agent／PTY／计费。没有跑 only-my-pi 仓库测试。交付源码未上传或复制任何项目仓库。

HTML 尝试将演示状态存储于 localStorage，受限时退化到页面内存。恢复页面不会重启未完成任务或继承待确认授权；模拟终端标签仍为当前页面状态。附件入口仅记录名称，不上传内容。截图均由 HTML 实际渲染，非原生 App 或生成式效果图。
