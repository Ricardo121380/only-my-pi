# U0 Glacier 对话优先设计合同

日期：2026-09-26。性质：**交互设计，不是已接入产品**。依据：[Q1–Q23](../../plans/2026-09-26-webui-optimization-discussion.md)、[既有视觉规范](pi-agent-glacier-design-spec.md)。[可交互样稿](u0-workbench.html)只使用合成内容，无 Host、模型、终端或文件写入连接。

## 视觉与空间

保留 Glacier 的蓝灰背景、柔和玻璃控件、稳定正文面板和圆角输入区；不改品牌、不增加装饰性渐变或第三方组件库。沿用生产 `webui/src/prototype.css` 的色值：亮色背景 #F4F6FB、正文 #202A3B、次级文字 #616E83、主色 #3D64D8；暗色背景 #141923、面板 #1C2330、正文 #E9EEF7。字体沿用系统 SF/PingFang，不依赖在线字体。

| 尺寸 | 导航 | 对话 | 审查/设置/材料 | 终端 |

| 1440px | 左侧262px，项目与会话 | 居中最大840px；输入区与正文同轴 | 默认关闭；按需侧面工作区，最多占屏幕一半 | 按需底部区域，独立关闭视图和停止会话 |

正文14–15px，标题22/32px，辅助12px；间距基于4/8px。交互目标至少40px，窄屏44px。边框和阴影表达层级，不用颜色单独表示状态。页面不横向溢出，代码/diff独立滚动。生产实现使用可调整面板并持久保存尺寸；样稿验证默认布局，不冒充已经实现尺寸持久化。

## 组件职责与状态

| 组件 | 职责/动作 | 必备状态与禁止混淆 |
| --- | --- | --- |
| WorkspaceNav | 项目、会话、搜索、新建；设置位于底部 | loading/empty/error/archived；切会话不隐式发消息或清草稿 |
| ConversationHeader | 会话身份、继续目标、审查入口 | 已停止历史默认继续；新建是独立动作；账号缺失明确 |
| TaskTimeline | 当前步骤、等待原因、文件变化、验证结论 | 无虚构百分比；工具详情按需展开；审批、工具执行、等待模型分开 |
| Composer | 草稿、模型/思考强度、权限、材料、发送 | 空/编辑/解析/超限/不支持/提交中；禁用附原因；IME composing 不提交 |
| InputQueue | 即时补充和排队、待投递编辑删除 | 已接收≠已消费；已投递不能假撤回；异常暂停，不重放 |
| MaterialPanel | 解析状态、范围、预览、来源和内容快照 | 全部/部分/失败/超限；不静默截断；材料清理后显示不可用 |
| ReviewPanel | 任务摘要、文件diff、命令与回执 | 已修改≠验证通过；用户修改不归因于Agent；未知不重试 |
| UsagePanel | 当前任务与会话、主/子Agent、数据来源 | 缺失显示未知，非0；估算非账单；继承历史不算新增 |
| CapabilityPanel | 默认配置、项目覆盖、实际加载反馈 | 后续执行生效；强制能力无禁用开关；无Schema不展示假编辑器 |
| TerminalDock | 真实PTY、连接/重连/退出；人工占用提示 | 关闭面板不结束终端；结束需进程清理回执，不伪造终端输出 |

## 样稿场景与可验证动作

工具栏「查看场景」是设计评审工具，不进入产品：新会话、历史会话、执行中、等待审批、材料待处理、结果审查、失败恢复、设置。场景切换只替换合成状态。

- 首页用任务建议启动草稿；新建明确清空当前演示会话，不与继续混用。
- 执行中输入可明确选择「即时补充」或「排队」，展示待生效和独立停止；详情不会占满消息流。
- 审批直接列作用范围和确认按钮；用量和权限不是同一弹层。
- 材料超限显示原因和范围处理；结果摘要链接到文件差异。
- 失败页保留已完成步骤，队列暂停；「核对后继续」是演示状态转换，不真实重跑。
- 所有未接后端的演示操作均明确标记；不能以样稿里按钮有反馈验收U1–U5功能。

## 键盘、动效与实现约束

使用原生button/select/textarea/dialog语义，焦点环2px且不被遮挡；模态自动聚焦、Tab圈定、Escape关闭、返回触发点。状态更新使用polite live region，不自动抢走输入焦点。生产发送快捷键提供可见说明并测试真实IME。

沿用120ms按压、190ms控件、300ms布局上限；本稿仅使用颜色/阴影短过渡，不动画流式token或大列表。`prefers-reduced-motion: reduce` 禁用过渡；加载有静态文字，不能依赖旋转标识。

U1起按职责抽取状态和组件，不提前替换整个App。新增消息/草稿状态归Host合同，视图开闭归客户端。长消息/日志虚拟化在真实样本测量后定向实施，不把每个流式块接到顶层App重渲染。

使用 ui-ux-pro-max 的焦点/可见性规则及 frontend-design、frontend-ui-craft 的层级和完整状态要求。React关键词检索两次无匹配，因此不引用不存在的技能数据库结果；后续React实现依据现有组件和专门的React规则。
